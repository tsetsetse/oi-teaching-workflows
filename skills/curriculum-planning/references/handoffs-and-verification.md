# 交接与验收

| 接收模块 | 输入 | 返回与边界 |
| --- | --- | --- |
| lesson-preparation | 单课目标、来源单元、前置证据、课时、任务和达标观察 | 详细讲义与程序核验；规划任务不默认生成整阶段讲义 |
| courseware-delivery | 已确定讲义/解析、展示目标、时间和既有视觉方向 | 课件与备注/验收；新设计遵守其选型规则 |
| practice-assessment-feedback | 阶段检查节点、目标与知识关系、评价依据、实际作答/观察 | 具体任务、教师诊断、补练和家长草稿；设计与实际学情分开 |
| contest-exam-analysis | 指定题目/试卷、版本、评分与训练目的 | 详细答案、分层完整实现及证据，不推出学生已经掌握 |

通过当前环境发现并读取，解包源码可读同级目录。缺模块时完成可做的规划，列出对应制作阶段未完成；不假称调用或自动安装。

## 交付前逐项核对

1. 本次是标准层还是实施层，是否保留源结构、身份、题目和内容映射；新增建议是否标清，成熟讲义是否被未经授权改写。
2. 目标与任务/检查一一对应，核心和拓展分清；无具体学生数据仍可交付标准母版，个人状态不超出证据。
3. 必需前置与教材顺序分清；未来能力是条件，不是现状。已授、提示、订正与独立复验分开。
4. 单课活动、章节范围与总时间计算一致；诊断、测评、订正和机动不重复计时或被隐去，作业不冒充课堂。
5. 冲突与取舍可见，固定约束和已有授权得到遵守；后延目标有去向，不能保证未测情况下全部完成。
6. 续做保留已发生记录，只修改未来/受影响部分；来源变化的影响、实际时长未知与待决定事项都保留。
7. 仅规划/只读/仅家长范围得到遵守；计划未扩大成完整课件、评测系统、日历或外部发送。

数值与结构检查只能证明相应一致性，知识顺序和任务难度要人工审查，真实达标与教学有效性需要实际学习记录。若额外编译运行代码，显式清单与对应语言/环境的证据另记，不把编译当学习证据。
