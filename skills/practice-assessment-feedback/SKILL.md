# 作业测评与学情反馈

把学习目标转成可检查的作业或测评，再依据实际作答、课堂观察等个人表现证据形成具体诊断、可执行的教学调整和温和鼓励的家长反馈。设计阶段确定“检查什么”，反馈阶段依据证据说明“掌握怎样”。

## 1. 确定本次场景、范围与事实

读取目标项目适用的 `AGENTS.md`、本课讲义/训练目标、已学范围、指定题目/试卷、评分约定，以及本次实际提供的学生作答、代码版本、课堂观察和已有记录。记录来源与版本；按学生和课次/测次分开，保留原稿、原始作答和历史报告。

从 [四类场景与评价蓝图](references/assessment-modes.md) 选择 `homework`、`checkpoint`、`exam-mock` 或 `contest-mock`。沿用已确认的课时、学生基础、语言、题量、考试身份与输出位置；关键缺项才问。默认在课程项目的本次作业/测评目录保存资料，已有命名优先；真实学生材料不写入技能目录或工作流源码仓库。

| 本次请求 | 本次交付 |
| --- | --- |
| 只读讨论/审阅 | 对话中的依据与建议，不写课程文件 |
| 仅设计作业/测试 | 学生任务、教师答案/程序、评价与测试方案；没有作答时不写孩子实际表现 |
| 仅批改/教师诊断 | 按证据批改，详细问题分析、教学调整、补练与复验；明确限定不出题时遵守该范围 |
| 仅家长反馈 | 依据现有记录生成指定文字，不强制另做试卷、教师报告或网页 |
| 完整作业测评与反馈 | 在实际材料支持的阶段完成设计、核验、诊断、教师版和家长版；缺少个人表现证据时保留学情待补，只有观察时完成其支持的反馈 |
| 续做/订正后复查 | 比较题目、评分、代码和观察版本，只更新受影响结论；旧结果与新结果分别保留 |

必要时用 [事实记录模板](assets/evidence-template.md) 梳理题号、作答、提示程度、检查结果与来源。没有记录的耗时、求助、态度、进步或课堂言行保持未知；单次测试不推出长期能力或性格。缺个人表现时可以交付课程说明、待补事实和记录模板，不能用想象填成个体学情。
只有课堂观察、没有作答文件时，按观察支持的范围写反馈，不强制出题或补交文件；程序正确性、分数和未观察行为仍待相应证据。

## 2. 设计任务与评价依据

按 [评价蓝图模板](assets/assessment-template.md) 建立“学习目标/知识点→题目→期望观察→评分或达标依据→验证方式”，按实际需要组织基础巩固、独立应用、迁移和拓展；数量与难度服从本次要求和已学范围。

选题、改编与原创分别标明来源和变化。学生卷与教师答案分开；编程题包含完整题意、I/O、样例、范围与适用子任务，绘图/平台任务写操作和预期结果。教师版包含完整参考程序、关键思路、错误反例与检查用例，不只给题号或链接。严格对齐考试时核对对应官方来源；自编模拟不能当官方卷或预测通过保证。

通过当前环境或同级技能目录按需读取模块：本课目标来自确定的 `lesson-preparation` 产物；建模与方法用 `solve-with-computational-thinking`；CSP第二轮原创/改编题包、数据和验题用 `csp-contest-author`；确定题目的逐项答案、多视角和分层完整代码可交给 `contest-exam-analysis`，GESP逐选项分析可复用 `gesp-solver`。这些模块不替代本次蓝图，不把其默认题量、分值、版本套到所有作业和考试。

## 3. 核验与批改

按 [核验与证据边界](references/verification.md) 检查题面、答案和评分；代码审阅后提供显式用例清单，使用可用的讲义检查器或对应环境实际执行。学生错误程序保留原样，错误输入、预期、实际结果及订正版本分别记录；编译通过不当作答案正确。

按给定评分规则逐项评定，保留题号、知识点、失分依据、订正状态与独立程度。缺答、未测、未学、提示后完成和独立完成分别标记；没有缺交计零规则时不自动记零。缺项影响总分时只报告已核验部分和缺失分母，不用缺答推断不会或态度差。模拟分数、理论分层覆盖、本地运行与正式评测分别说明，不相加不同程序的分数。

## 4. 详细教师版与鼓励型家长版

先读 [反馈内容与表达约定](references/feedback-contract.md)，按本次要求使用 [教师诊断模板](assets/teacher-feedback-template.md) 和 [家长反馈模板](assets/parent-feedback-template.md)。仅需其中一版时遵守范围。

教师版对每个主要问题写清：具体表现和证据→已证实原因/待确认假设→下一步教学改动→需要补练的具体知识关系→可直接使用的完整习题、提示、答案/完整程序和测试→复验标准及通过/未通过后的安排。把“多练循环”细化为起点、判断、更新与执行次数等具体关系；习题覆盖原错误、边界和有意义的迁移，保持学生知识范围，不把所有循环机械改成同一种条件。列出优先级和实际教学顺序，未实施的调整写为计划。

家长版用自然教师口吻、通俗语言和适合微信复制的纯文本，保留学习内容、实际完成、具体亮点、需要继续巩固的环节、下一步学习与必要家庭配合。鼓励绑定真实表现和有效努力，委婉说明具体问题与老师的帮助安排；不用空泛夸奖、性格标签或保证结果代替事实。提示后订正不能写成独立掌握，没有历史记录不能写比上月进步。评分和关键失分原因保持准确，篇幅/标题沿用户要求，不固定字数。

## 5. 复验与交付

使用 [验收记录模板](assets/verification-template.md) 分开记录来源与人工审查、程序实际执行、评分依据、反馈事实核对、待完成与未测项。新增学生作答/订正后回到受影响题目复查；独立复测未发生时保持待复验，不提前改成已掌握。

需要交互时把已确认的代码、数据、状态和观察目标交给 `interactive-algorithm-demo`；需要修订讲义或PPT时将具体位置和教学改动交回对应工作流，沿用当前授权，不把反馈默认扩成重做课程。由 `teaching-workflows` 交接进入时共用任务进度和来源。

交付本次要求的学生任务、教师答案与测试、详细教师诊断、家长文字或其待补事实，附必要核验与下一步。家长文字作为草稿交给用户，不代为发送；GitHub同步、安装、外部发布、定时任务不由本流程自动附带。
