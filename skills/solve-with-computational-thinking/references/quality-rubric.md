# 计算思维题解质量量表

## 目录

1. 硬门槛
2. 二十分量表
3. 模式专项检查
4. 代码与教学检查
5. 交付结论

## 1. 硬门槛

出现任意一项时不得宣称题解完整：

- 题面、数据范围或操作契约缺失，却把假设当成事实。
- 算法前提与本题模型冲突。
- 完整代码无法编译、无法运行样例，或与解释不是同一算法。
- 最优性只有直觉或样例，没有正确性论证。
- 复杂度无法适配已知数据范围，却没有明确说明限制。
- 搜索状态或动态规划状态遗漏了影响未来的信息。

## 2. 二十分量表

每项按 `0 / 1 / 2` 评分：

- `0`：缺失或错误。
- `1`：提到了，但没有具体证据或与后文连接较弱。
- `2`：具体、正确，并直接推动后续推理。

| 项目 | 2 分标准 |
|---|---|
| 题目契约 | 目标、输入输出、范围、操作和特殊情况明确 |
| 手工模拟 | 展示状态变化，并能检验题意理解 |
| 问题分解 | 子问题清楚，指出核心困难 |
| 抽象建模 | 对象、状态、关系、约束和舍弃信息合理 |
| 朴素解法 | 方法正确，复杂度推导完整 |
| 瓶颈定位 | 量化指出重复工作或不可承受部分 |
| 模式识别 | 候选算法有结构证据和守卫条件 |
| 算法设计 | 数据结构、顺序、更新、终止完整 |
| 正确性 | 论证覆盖不漏、不错及最优性要求 |
| 实现评估 | 模型到代码、复杂度、边界和迁移完整 |

解释：

- `18–20`：推理链完整，可进入代码和版式终检。
- `14–17`：可用但仍有明显教学断点，修正后交付。
- `10–13`：更像答案摘要，需补建模或正确性主线。
- `<10`：算法可能偶然正确，不适合作为教学题解。

分数不能覆盖硬门槛；即使总分高，触发硬门槛仍必须修复。

## 3. 模式专项检查

### 搜索和最短路

- [ ] 状态、转移、起点、目标、合法性全部明确。
- [ ] 判重键包含所有影响未来的信息。
- [ ] 边权类型与 BFS、01-BFS 或 Dijkstra 匹配。
- [ ] 不可达行为明确。

### 贪心

- [ ] 局部选择写成可执行规则，而非口号。
- [ ] 有交换、领先、反证或其他适配证明。
- [ ] 用反例检验相似但错误的策略。
- [ ] 操作模型与证明完全一致。

### 动态规划

- [ ] 状态含义是一句话可验证的命题。
- [ ] 初始化、转移顺序和答案位置一致。
- [ ] 不可达状态不会参与非法转移。
- [ ] 能说明为何状态足以决定未来。

### 二分

- [ ] 搜索对象是值、位置还是答案边界。
- [ ] `check` 的真假分布和单调方向明确。
- [ ] 区间不变量与返回值一致。
- [ ] 极端边界不会死循环或漏答案。

## 4. 代码与教学检查

### 代码

- [ ] 关键变量可映射回模型。
- [ ] 下标、初始化、溢出和无解情况检查完成。
- [ ] 代码语言和平台环境标注正确。
- [ ] 完整程序通过语法检查和代表性运行。
- [ ] 样例、边界和反例至少各覆盖适用项。

### 教学

- [ ] 学生在看到算法名之前经历题意和建模提问。
- [ ] 每个核心判断有问题、预期回答和追问。
- [ ] Bug 不只给错误代码，还解释错因和最小反例。
- [ ] 板书保留推理主线，而不是只列模板。
- [ ] 练习包含模仿、变式和综合层次。
- [ ] 核心推导展开，仅练习答案折叠。

## 5. 交付结论

使用以下格式结束自检：

```text
硬门槛：通过 / 未通过（列出项）
量表得分：__/20
已运行验证：样例、边界、反例、编译/解释器
未验证内容：来源、平台 API、动态链接等
最需要学生复述的一句话：________
改变一个条件后的迁移问题：________
```
