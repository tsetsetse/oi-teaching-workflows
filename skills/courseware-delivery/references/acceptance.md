# 验收与失败处理

各层独立记录证据。只有文件存在、结构通过、代码样例通过或渲染成功中的一项，不代表整个课件已经验收。

## 验证实际成品

| 层次 | 必须核对的内容 | 证据边界 |
| --- | --- | --- |
| 内容与教学 | 对照讲义核对题面五字段、多组样例、语法范围、公式/状态、代码、预测顺序、练习与课时；检查核心作品/任务、改进理由、同题再验证与学生表达 | 人工引用对应页码/步骤；不以标题数量或最终作品画面代替理解过程 |
| 视觉设计（适用时） | 新视觉的真实方向稿、用户选择/豁免记录，以及按 huashu-design 执行的视觉检查 | 仅分镜不要求方向稿；方向选择不证明整套课件已通过 |
| 程序与状态 | 从最终课件/配套中取得完整代码，确认显示内容一致，按约定版本运行公开样例与关键边界；逐步核对表格/演示状态 | 预期来自原题、手算或独立方法；错误教学演示不混作标准程序 |
| 编辑性与备注内容 | 从真实PPTX核对代码、数值、状态表/公式为可检查、可编辑对象，并逐页读回原生备注内容 | HTML中的文本/备注或整页图片不证明PPTX满足要求；非空备注不等于讲稿齐全 |
| PPTX包 | 备注正文、必要部件、内嵌媒体、包内目标与本地附件链接 | 结构通过不证明备注讲稿齐全、文件完全符合所有OOXML规则或PowerPoint可播放 |
| 渲染与观感 | 渲染最终文件并逐页查看换行、溢出、遮挡、代码、表格与字号；检查关键揭示状态 | 记录渲染环境；不把自动检测/缩略图或静态PDF当作原生点击验证 |
| 携带使用 | 把交付目录复制到独立临时位置，从副本运行检查并重新渲染/打开，核对相对附件；有联网资源时明确依赖 | 不移动、删除或改权限让原始资料失效；副本测试结合依赖扫描判断可携带性 |
| 演示（如有） | 实测前进/回退、重置、输入变更、错误输入、代码/状态同步及离线打开 | DOM/算法自检与真实浏览器交互分别报告 |
| PDF（如有） | 页数/内容对应、关键状态、答案与备注包含范围、文字可读 | 静态材料不具有动画、交互或演讲者视图 |

字体替换、原生 PowerPoint 播放、双屏备注显示和实际教室投影有对应设备时验证；没有条件时列为未验证，不能从普通渲染推定通过。
实际课堂效果、学生掌握情况与20/40/90分钟能否按时完成，需要试讲或课堂观察；模板与自动检查不提供这些证据。

## 只读 PPTX 检查器

```sh
python3 <技能目录>/scripts/check_pptx.py <课件绝对路径>
python3 <技能目录>/scripts/check_pptx.py <课件绝对路径> --bundle-root <交付根目录>
```

默认交付根目录为 PPTX 所在目录。课件在 `output/`、演示在同一交付目录的 `demos/` 时，显式指定共同父目录。
检查器只读取 ZIP/XML 和附件是否存在，不联网、不解压写盘、不渲染、不执行讲义或附件代码。

- 按主演示文稿的关系顺序检查幻灯片，并按每页的关系寻找教师备注；不假设 `slide1` 必然对应 `notesSlide1`。
- 检查必要部件、ZIP完整性、XML所引用的关系ID、包内关系目标、逐页非空备注正文；备注字数不能证明教学内容充分。
- 拒绝外链图片、音视频及其他外部资源依赖。网页来源链接保留并单列，不将它们误称为内嵌资源。
- 本地附件须以相对链接存在于交付根目录内；`file:`、作者绝对路径、缺失附件和越出交付目录均失败。其他协议链接单列，仍需按授课环境核实。
- JSON 中的 `checks_passed` 仅表示该工具范围内未发现错误；返回0不等于文件视觉、代码、交互或原生播放验收完成。

## 失败后的处理

1. 先区分来源/题面问题、生成错误、文件缺件、代码/状态分歧、版式问题与环境能力缺失。
2. 对生成错误定位具体页、部件、代码或首个分歧步骤，修复本次获准修改的部分，再重跑失败项和受影响检查。
3. 内容过密优先分段或拆页；不要用裁剪、转成不可检查的整页图片或缩小到难以投影的字号掩盖问题。
4. 图片/附件缺失时嵌入资源或纳入交付目录，修正相对路径，重新检查并复验复制件。
5. 源讲义有关键歧义时列明影响，不把自行猜测的条件写成原题；可继续完成不受影响部分。
6. 缺少工具或设备时保留可用产物，说明未验证的具体项及使用影响；不得伪称实际运行、渲染或播放通过。

多课件打包时只纳入选定最终版和必要附件，另存构建/历史；检查归档完整性、包内路径、所需文件和最终指纹。
