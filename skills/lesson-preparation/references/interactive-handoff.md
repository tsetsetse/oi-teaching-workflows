# 备课讲义与交互演示的交接

讲义确定教学主线、题意、代码与讲稿；`interactive-algorithm-demo` 把需要观察的过程做成可操作网页。通过当前环境或用户指定位置读取该技能及实际需要的资源，不复制技能正文或绑定作者安装路径。

## 什么时候使用

用户明确要求交互时遵守其范围；一般备课按教学难点选配，例如循环/递归顺序、代码与图形变化、搜索队列、DP 转移、对比输入与反例。短概念或简单静态说明可用原讲义追踪表，不要求每课都生成网页。只读审阅/仅规划只写使用建议，缺关键题意时先解决契约，不能用动画替代确认。

## 输入、产物与讲稿

给演示技能的简报包含：本课学生和已学语法、题目/段落、原始条件、选定方法与完整代码版本、输入输出/下标/状态含义、演示案例与手算预期、观察目标、操作需求和保存位置。多个分层或替代方法中明确本演示选哪一个；演示上限与原题范围分开写。

产物默认自包含离线 HTML，存目标项目现有附件位置；无约定时用课程目录的 `附件/交互演示/`。在本次授权的讲义中使用相对链接，记录“打开时机 → 输入 → 学生先预测 → 教师/学生操作 → 观察结果 → 回到讲义的结论”。原稿不因增加演示被覆盖；引用和嵌入方式遵守项目约定。

返回并实际读回网页、使用说明和验证证据，核对显示的代码、变量、图形和解释对应同一步；前进/回退时答案同步揭示/撤回，错误输入保留原有效数据。已有有效演示可复用，核对契约与受影响部分，不重复生成。

## 验收分工

- 讲义：来源、题面、推导、状态、代码、课堂预测、使用时机和链接。
- 演示：算法对照、独立步骤快照、前进/回退/跳转/播放/重置/改数据、错误输入、代码高亮与解释同步。
- 环境：真实浏览器与实际窗口、离线打开和复制件分别记录；截图或纯算法测试不能代替控件交互。

从实际显示的完整程序提取并按约定语言版本核验；JS 过程模拟不称为实际执行 C++。没有浏览器或图形环境时保留已完成部分并标未验证；静态关键步骤仍留在讲义。需要做 PPT 时再进入可用 `courseware-delivery`，沿用同一演示和题意。
