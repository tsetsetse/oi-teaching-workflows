# 让知识回应项目需求

设计项目或把讲义改成项目课时读取。先锁定本课目标，选择能在课时内制造学习需要的功能；项目大小由认知负担、允许语法和独立验收时间共同决定。

## 每项核心知识的设计卡

| 字段 | 需要作出的决定 |
| --- | --- |
| 功能需求 | 孩子想让作品做到什么，使用者能观察到什么 |
| 当前困难 | 用已有知识尝试后，在哪一步还做不到/容易出错 |
| 引入机制 | 新知识恰好解决哪一处困难，哪些部分继续用旧知识 |
| 先预测/操作 | 引入写法之前，学生如何理解过程并提出猜测 |
| 代码与状态 | 情境对象对应什么变量/结构，关键步骤前后改变什么 |
| 版本结果 | 完成本版后能运行/观察什么，哪些需求尚未实现 |
| 通用规则 | 脱离角色名字后，学生能复述什么机制与适用条件 |
| 独立迁移 | 撤去什么支架，换什么条件，取什么证据判断理解 |

每个本次核心知识都有对应关系，辅助知识按需要说明，不为填表增造功能。把故事名称换掉后，功能需求仍应能说明为什么要用新知识。单纯先讲语法、末尾把练习改成角色名字时，回到“当前困难”处重新组织引入。

## 三种规模，两个设计入口

- 单课微项目：一个清楚的功能缺口，少量紧密关联的新知识；由预测到独立实现走完一轮。
- 连续升级：一个作品跨若干课，每课有自己的核心目标、能运行的小版本与退出检查；跨课路径由规划模块组织。
- 操作实验：机制难以直接看见时，用代码/状态/结果对应的实验先建立模型，再回到任务。实验也要有需要回答的问题。

已有讲义改造：先保留知识、题目、样例和来源映射，调整出场顺序与支架；需要实质改变条件时按项目规则处理。围绕目标新设计：先确定知识与可观察表现，再选情境，不先造大作品后塞入大量未学语法。

## 选择版本与撤架

版本按有教学价值的缺口拆分，不固定V1/V2/V3数量。每版包含学生操作、教师支持、程序/步骤、执行状态、可见结果和下一缺口。运行界面可以由教师提供，讲义明确它做了什么、学生承担什么；后台隐藏目标知识会使独立证据失真，应改为明确的教师支持。

常用推进是：试玩/观察目标→旧方法完成一个小部分→暴露需求→预测/手工过程→对应新语法→完成新功能→解释/排错→撤架独立应用→提炼规则与迁移。允许按课程合并，关键证据保留。

独立任务使用已确认条件，保留必要资料和实际允许的支架，收起完整答案与关键步骤模板。记录真实提示类型，局部填空只支持局部能力；迁移要检查机制判断、状态设计或条件变化，不只改台词。

## 调整与复盘

时间表给出每段预算和可检查成果；家庭作业另列。进度慢时优先减少装饰和非核心功能，保留独立检查；需要缩核心范围时保持后延目标可见，不把缩减版写成全部完成。

记录兴趣的具体信号、第一次预测、最早出错状态、提示内容、修复及复验结果和实际耗时。用这些证据决定下一次改哪个讲法、支架或题目；没有实际记录时只给预期检查与调整分支。
