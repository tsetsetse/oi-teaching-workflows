## 1. 使用原则

计算思维不是四个术语，而是一条可复现的推理链：

```text
题目事实 → 小例子 → 分解 → 建模 → 朴素方法 → 瓶颈
        → 结构识别 → 算法 → 正确性 → 代码 → 评估与迁移
```

四个经典维度贯穿其中：

- **分解**：把复杂目标拆成可验证的子问题。
- **模式识别**：发现重复计算、相似结构或可复用关系。
- **抽象**：留下决定答案的信息，建立状态和关系模型。
- **算法设计**：把模型转成有限、明确、可执行的步骤。

再补充三项防止讲解停在口号层面：**评估、正确性、迁移**。

## 2. 十阶段分析卡

### 2.1 题目契约

逐项填写：

- 目标：求值、计数、判定、构造，还是最优化？
- 输入：对象是什么，数量和取值范围是什么？
- 输出：格式、精度、无解行为是什么？
- 操作：一步允许做什么，代价如何计算？
- 边界：下标、重复、负数、空集、不可达、溢出是否可能？
- 信息状态：原题明确、合理推断、仍待确认分别是什么？

### 2.2 手工模拟

优先选择能暴露规则的最小案例。用表格记录“当前状态—执行操作—新状态—累计结果”。若存在两种解释，选择能让两种解释产生不同答案的案例。

### 2.3 问题分解

常见拆法：

- 按流程：读入 → 预处理 → 核心计算 → 输出。
- 按目标：可行性 → 最优值 → 方案恢复。
- 按对象：每个元素、每个区间、每个状态、每个连通块。
- 按困难：枚举对象、快速查询、避免重复、维护合法性。

指出决定整体复杂度的子问题。

### 2.4 抽象与建模

至少回答四个问题：

1. 一个状态需要哪些信息才能决定后续？
2. 哪些操作会让状态发生变化？
3. 哪些信息与答案无关，可以删除？
4. 什么性质在操作前后始终成立？

常用模型包括数组扫描、区间、集合、图、树、状态空间、选择序列和最优子问题。先定义模型，再匹配算法。

### 2.5 朴素解法

说明枚举对象、每次计算内容、正确性直觉和复杂度。例如：枚举所有区间有 $O(n^2)$ 个；若每次再扫描区间，总复杂度是 $O(n^3)$。

### 2.6 瓶颈定位

使用可量化句式：

> 朴素方法重复计算了 ______；这一部分被执行 ______ 次，每次需要 ______，因此形成 ______ 的复杂度。

### 2.7 模式识别

模式必须带证据：

- 观察：出现了什么稳定结构？
- 对应：它与哪个已知模型一致？
- 条件：该算法的前提在本题是否成立？
- 排除：最相似的错误算法为什么不适用？

### 2.8 算法设计

写清数据结构、处理顺序、更新规则、终止条件和答案位置。伪代码中的每个名称都应能在模型中找到来源。

### 2.9 正确性与反例

正确性说明必须覆盖：

- **不漏**：所有合法候选都会被考虑，或被安全地代表。
- **不错**：每次保留、删除或转移都满足约束。
- **最优/唯一**：若要求最优，说明为何更优候选不可能存在。

再尝试构造反例。找不到反例不是证明，但找到反例可以立即淘汰错误策略。

### 2.10 评估与迁移

给出时间、空间、边界、实现风险和适用范围。最后改变一个条件，例如把等权变成不同权、把静态查询变成在线修改、把求一个解变成求方案数，判断模型和算法是否仍成立。

## 3. 正确性论证选择

| 算法类型 | 常用论证 | 必须回答 |
|---|---|---|
| 枚举 / DFS | 覆盖性、互斥性 | 是否枚举全部合法方案？是否重复？ |
| BFS | 分层不变量 | 为什么第一次到达就是等权最短？ |
| 01-BFS / Dijkstra | 松弛与最短路性质 | 边权条件是否满足？何时距离确定？ |
| 贪心 | 交换、领先、反证 | 局部选择为何能替换某个最优解的首步？ |
| 动态规划 | 状态完备、转移无遗漏、归纳 | 状态是否包含决定未来的全部信息？ |
| 二分答案 | 单调谓词、边界不变量 | `check(x)` 是否真的单调？返回哪一侧边界？ |
| 单调栈 / 队列 | 候选支配关系 | 被删除的候选为什么永远不可能再成为答案？ |
| 并查集 / MST | 连通不变量、割性质 | 合并或选边为何不破坏目标？ |

## 4. 数据范围到复杂度

不要使用绝对阈值冒充平台保证。应根据时间限制、语言、常数和数据结构给出量级判断，并明确它是估算。

常见推导方式：

- 明确枚举层数，写出 $n$、$m$ 或状态数的乘积。
- 把“每个元素最多入队一次”等均摊事实写入复杂度依据。
- 图算法同时写顶点数和边数，例如 $O(n+m)$、$O(m\log n)$。
- 状态搜索先算状态维度总量，再乘每个状态的转移数。
- 检查乘法、距离、方案数是否需要 `long long` 或更大范围。

## 5. 模型到代码

先制作映射表：

| 模型概念 | 代码表示 | 更新时机 | 不变量 |
|---|---|---|---|
| 当前状态 | 变量或结构体 | 取出待处理状态时 | 字段含义固定 |
| 最优记录 | `dist` / `dp` / `best` | 找到更优候选时 | 保存已知最优值 |
| 合法性 | 条件函数或判断 | 转移前 | 非法状态不进入容器 |
| 判重键 | `vis` 或完整状态下标 | 入队或松弛时 | 不丢失影响未来的信息 |

解释一轮关键循环：读了什么、判断了什么、更新了什么、为什么安全。

## 6. 信息不足处理

- 缺数据范围：不能确定目标复杂度，先给条件化选择。
- 缺操作定义：列出不同解释，并构造区分样例。
- 缺来源：不标注具体比赛年份或题号。
- 缺完整题面：可以讲通用方法，但不要声称已解决原题。
- 缺运行环境：区分标准语言代码与平台专有 API。
