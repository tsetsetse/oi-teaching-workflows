# 项目教学与作品验收

让孩子知道每个本次学习的知识帮助解决什么问题，并在完成任务中理解、解释和迁移。情境产生真实的功能需求，知识使作品前进一步；作品结果与学生学习证据共同参与验收。

## 1. 沿用范围与选择入口

先读目标项目的AGENTS、指定材料、已有记录，沿用语言/版本、课时、学生基础、允许语法、来源指纹、输出位置和授权。已授、能独立使用、提示后完成及未测分别记录；缺少个人数据仍可设计课程，不能生成个人掌握结论。

| 本次请求 | 工作范围 |
| --- | --- |
| 讨论、先审阅后决定 | 只在对话中给设计或有证据的问题，不写课程文件 |
| 仅规划 | 交付本次获准的项目设计；不自动生成整套讲义、代码、PPT或网页 |
| 改造已有讲义 | 保留原稿和已确认题目，重组需求、知识引入、版本、练习与验收 |
| 围绕知识点创建项目课 | 完成本次项目方案、学生任务、所用版本程序、授课内容和验收记录；任务卡可置于讲义内 |
| 验收已有作品 | 根据实际代码、测试、观察与提示记录评价；缺证据列待核对，不强制重写课程或补造学生结果 |

## 2. 从知识目标设计项目

读取[学习设计](references/learning-design.md)，使用[项目设计单](assets/project-design-template.md)。给每个本次核心知识建立“功能需求→当前困难→新机制→作品变化→解释与迁移证据”的对应关系。先让学生预测、手算或尝试旧方法，再在缺口处引入知识。

Python覆盖变量、表达式、输入、条件、循环、字符串、容器、函数等实际课程范围及综合应用；Turtle衔接只是一个场景。按难度选择独立小项目、同一项目连续升级或操作实验，不要求每个知识点新开大型作品。C++按基础语法、算法应用、综合实践选择深度。读取[语言与阶段适配](references/language-paths.md)的当前路径，不把两种语言或不同阶段的要求混为一套。

新增/改编题目的条件按目标项目确认规则处理；已确认不重复询问。正式编程任务写全输入、输出、范围、样例及必要说明；演示、纸卡和图形操作按实际初始状态/动作/结果描述，不伪造标准输入输出。

## 3. 安排能检查的版本与教师支架

把核心功能拆为适量的小版本，每版写清已有能力、需要解决的缺口、学生动作、可运行代码或操作步骤、状态与可见结果。演示片段标依赖；观察版本与正式任务输出不同时明确切换和清理步骤，不能把中间成果当作完整交付。

用同一数据对齐代码、当前值/结构、执行动作和输出。板书、纸卡即可支持观察；按难点和用户要求选用交互演示。教师提供的显示界面、起始代码、初值、英文名或辅助程序逐项标明，并说明学生独立负责的部分。

时间包括引入、理解/追踪、实现、调试、撤架独立练习、迁移与验收，合计符合本次课时。支架逐步从示范到提问、局部提示再到撤去答案；保留足够的独立证据。超时先处理取舍并核算，不能把迁移验收默删后仍称全部达标。

## 4. 以四类证据验收

用[验收与复盘单](assets/acceptance-template.md)，读取[交接与核验](references/handoffs-and-verification.md)。

| 维度 | 应取得的证据 |
| --- | --- |
| 功能 | 所需功能、输入输出/操作契约、状态与关键测试是否符合；C++同时核对适用范围和资源要求 |
| 解释 | 学生能说明模型、当前状态、关键语句、停止条件或算法理由，深度随课程阶段 |
| 独立程度 | 教师提供了什么，学生独立完成什么，用过哪些提示，订正后是否再独立复验 |
| 迁移 | 换数据、改变条件或换情境后能否提炼并应用同一机制；具体记录状态/代码/原话 |

先在情境中理解，再让学生提炼通用规则，最后用撤去方法名/范例的适量变式检验。作品能运行、改变外观或样例通过只支持相应维度；未测、失败、提示后完成和独立完成分别保留。仅有教师参考程序时只能核验程序，不能评价某个孩子。

## 5. 调用已有能力并续做

按[交接与核验](references/handoffs-and-verification.md)只读取当前需要的模块。多课路径交curriculum-planning，详细授课内容交lesson-preparation；模型与算法按需用solve-with-computational-thinking，PPT交courseware-delivery，实际学情与独立作业交practice-assessment-feedback。原卷解析及部分分交contest-exam-analysis，命题请求才用csp-contest-author。

交接同一知识范围、来源、任务契约、版本、状态、支架、时间、学生证据和验证记录；已确定的项目主线作为备课输入，避免相互转回已完成阶段。技能资源从环境发现或同级模块读取，产物写到使用者项目。

续做先核对来源/版本/作品与记录，只处理受影响部分；代码、规则、数据或输出变化时联动题面、状态表、样例与演示。最后交付本次产物和复盘证据，区分结构、实际程序运行、原生显示/浏览器及课堂未测。GitHub同步、技能安装和发送反馈按对应授权执行。
