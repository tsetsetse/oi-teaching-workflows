# 备课讲义工作流

把已有课程整理成可直接授课的讲义，并留下能够继续工作的检查记录。
目标项目的规则负责本地约定；本技能负责来源、教学设计、实现与验收之间的衔接。

## 1. 确定本次输入与边界

读取指定原稿、适用的 `AGENTS.md`、必要的前后相邻课程和课程模板。只读取与本课有关的资料。
记录原稿路径、课程编号、学生基础、已学语法、授课时长、用户要求、输出位置和来源指纹。
已有资料能确定的信息直接沿用；可自行决定的教学细节说明假设后继续，关键题面或学生阶段无法确定时才询问。
用户提供喜欢的讲义时，先提炼章节组织、认知递进、讲稿、板书、互动与答案呈现方式，再用于本课；参考讲义中的题面、技术结论和代码仍按本课来源独立核对。

| 当前授权 | 行为 |
| --- | --- |
| 先梳理、只读审阅、展示建议后再决定 | 在对话中交付建议；不写讲义、报告或其他课程文件 |
| 创建或修改讲义 | 完成编辑与验收；不因普通实现细节重复询问 |
| 续做已有任务 | 读取现有产物和检查记录，核对原稿是否变化，从尚未完成的阶段继续 |

默认保留原稿，在同目录另建 `<原文件名>-讲义版.md`；已有同名文件时先读取，按本次授权局部更新。
用户指定其他输出位置或要求覆盖时按其要求执行。记录用于本次任务，不默认写入整库配置或创建定时任务。

## 2. 锁定题面与教学主线

按需使用可用的 `solve-with-computational-thinking`；写 Obsidian 笔记时使用 `obsidian-markdown`，需要实际控制资料库时再用 `obsidian-cli`。
技能不可用时沿用本流程完成可做的工作，说明影响，不假称调用成功。

- 逐题核对题号、原始来源、完整条件、输入输出、数据范围、公开样例与特殊约定。图片或 PDF 有疑点时回看原件；不能用旧讲义代替原题核对。
- 主讲编程题、独立编程练习和编程作业使用完整题面。目标项目有题面字段约定时遵守；否则采用 **题目描述、输入格式、输出格式、公开样例、数据范围、子任务与说明**。
- 口头问答、读程序和局部填空可以简写。无输入任务写明无输入；绘图或平台任务写初始条件、操作与预期结果，保留平台依赖。
- 缺少影响解题的条件时保留“待核对”，完成其余章节，不把该题当作完整任务交付。新增或实质改变题目条件，按目标项目的确认规则处理；已确认的条件不重复请求。
- 从前置知识提炼贯穿全课的认知主线，按“情境提出问题 → 预测与观察 → 原理推导 → 方法与代码 → 纠错 → 练习迁移”安排内容。板书呈现核心认知、关系/状态对照、可迁移方法；各段时间合计符合本课时长，拓展按学生基础选用。

## 3. 写讲义与参考程序

新建或重构完整讲义时，先读 [教学结构与推导方式](references/teaching-structure.md)，再参考 [讲义模板](assets/lesson-template.md)。默认采用“教学目标与前置知识 → 板书思路与课时 → 逐段讲稿 → 课堂练习 → 课后作业 → 可选拓展 → 易错点总结”；按实际课程合并或删去无关部分，不留下空栏目。
局部修订保留原有结构；保留 frontmatter、创建时间、wikilink、图像嵌入、题号、外链和课堂情境。
Obsidian 练习答案沿用目标项目的折叠约定，核心推导保持展开。

每个核心段落给出可直接使用的教师讲稿、学生预测、预期回答与检查点。用具体数据的比较或状态追踪推出关键关系和写法，解释“为什么成立、为什么这样写、什么时候适用”，再映射到代码。
概念课围绕本课认知障碍设计；算法题从契约、手工追踪和朴素方法出发，说明瓶颈、选择、正确性与复杂度。多种写法只在有教学价值时比较，说明推荐理由和适用条件。
选择有代表性的错误，组织“先预测 → 错误运行结果/手算 → 逐步追踪 → 原因 → 最小修复 → 再验证”的 Bug 实验，随后用同题练习检查迁移；局部练习和总结回扣这一认知主线。
只用学生已学或本课明确引入的语法。正式题的程序输出严格遵守题面，课堂提示文字仅出现在明确标注的交互演示中。

模板与脚本路径相对本技能目录解析；原稿、附件、输出路径相对当前课程项目或用户指定目录解析。安装后不依赖源码仓库或作者本机路径。

## 4. 验证、修复与交付

写文件前先核对目标与授权，写后逐题核对完整条件、样例和学生知识范围。
静态检查可运行 `python3 <本技能目录>/scripts/check_lesson.py <讲义绝对路径>`；它只检查围栏、列出 C++/Python 代码块，不检查题面真实性、完整 YAML、链接可达性或教学质量。

审阅将执行的代码后，按 [检查与测试清单](references/verification.md) 编写用例清单，再用 `--cases <清单绝对路径>` 实际运行。
清单覆盖全部支持语言的代码块：完整程序实际编译/运行公开样例与关键边界；片段、故意错误代码和平台程序逐项写明跳过原因。复杂算法增加独立对照验证。
临时目录不是安全隔离，不能执行未审阅的外来代码。需要 Python 图形环境或平台 API 时使用对应环境；不可运行时明确标为未验证。

修复本次引入的问题，重新检查受影响部分；确认原稿未被意外改动。检查报告中必须分开记录已通过、跳过、失败和未验证项目；结构通过不代表完整讲义验收通过。
人工审查板书与讲稿是否一致、关键写法是否确有推导、预测是否在答案之前、Bug 是否解释状态变化并复验、练习是否检查本课目标；在验收记录中引用具体段落或数据作为证据。
创建任务参考 [验收记录模板](assets/verification-template.md) 留下来源、阶段、用例和下一步；只读任务在对话中报告。

最终交付讲义和检查记录的链接、主要教学变化、实际验证结果与待确认事项。程序测试通过不等于线上评测通过；只有实际查看过 Obsidian 阅读视图才报告渲染结果。
