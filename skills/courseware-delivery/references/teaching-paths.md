# 按学习目标选择教学推进方式

先确定学生下课时要完成什么、能解释什么，再选择路径。项目实践型适合围绕作品学习指令与设计；算法推导型适合围绕任务理解方法的由来、正确性与效率。路径不按 Python/C++ 划分，也不规定页数。混合课写清各段目的；基础短课只取相关环节，不为套结构新增作品、题目或算法。

## 项目实践型：作品逐步完善

| 环节 | 学生要做的事 | 分镜应留下的证据 |
| --- | --- | --- |
| 目标作品与观察拆解 | 看结果，比较差异，提出如何完成 | 目标效果、必要要求、待解决问题 |
| 最小可运行版本 | 用已知指令先完成核心功能 | 最小代码、预测画面/输出、实际验证结果 |
| 解释关键原理 | 从重复操作、执行顺序或状态变化解释现象 | 具体追踪、图形关系、指令与结果的对应 |
| 调整完善 | 围绕明确的新要求修改已有作品 | 改了什么、预期变化、验证后的变化 |
| 自主变化与展示 | 在已学范围内独立改动并解释作品 | 改动目标、个人实现、达标检查与口头表达 |
| 回顾与迁移 | 说出方法、困难及可复用经验 | 知识关系、同类任务或本课已有练习 |

新指令随作品需要出现，先保留可运行成果，再增加要求。展示可用“我做了什么 → 我的设计思路 → 遇到什么困难及如何解决 → 学到了什么”作表达支架，不能只展示最终画面。没有授权新增任务时，在原作品/原题内做预测、解释或变化。

## 算法推导型：同一任务反复验证

| 环节 | 学生要做的事 | 分镜应留下的证据 |
| --- | --- | --- |
| 旧知与核心任务 | 尝试已有方法，锁定题意与输入输出 | 完整任务、旧方法、适用规模与初始结果 |
| 暴露瓶颈 | 找到重复工作、错误条件或资源限制 | 具体输入/状态、操作数量或有环境说明的实测 |
| 状态演示与推导 | 预测下一步，说明怎样避免无效工作 | 同一数据的状态变化、关键关系、成立理由 |
| 方法与代码 | 把推导映射到变量、循环与条件 | 步骤和代码对应、正确性、边界与复杂度 |
| 回到原题验证 | 用新方法再次解决核心任务 | 同题结果与关键边界、优化前后对照 |
| 必要的进一步优化 | 从尚未解决的问题引出下一方法 | 剩余瓶颈、改动理由、再次验证；无需要则省略 |
| 练习、归纳与迁移 | 解释方法选择和关键条件，独立应用 | 预测、解释、补全程序或独立解题的达标证据 |

对照使用同一任务、同组核心数据与预期结果；需要扩大规模展示瓶颈时，单独说明规模与运行环境。来源截图中的耗时或通过结果只作来源信息，未经本次复验不写成本机实测。优化前先讲改动的理由，优化后回到任务核验；不把多个算法目录当作推导。

## 共用的改进记录与理解检查

每轮填写“已有成果 → 新问题/目标 → 学生尝试 → 验证结果 → 得到的方法”，并标注对应页码、代码版本与数据。尚未制作或运行时，结果写为预期和待验收，不能提前记为实测。

项目课检查学生能否解释设计与改动；算法课检查为什么正确、节省了什么工作、关键条件为什么必要。结尾用问题回顾或知识关系图归纳，再按目标选择预测结果、解释原因、补全程序、独立迁移等练习。为学生读题、思考、编码与表达留时间，配合原有 Bug 修复与复验，不要求每课凑齐所有形式。
