# 竞赛与等级考试解析核验

把指定原题或试卷整理成来源可追溯、逐题完整、推导可讲、程序有证据的中文解析。默认交付 Markdown 解析、编程题各层完整程序和必要核验记录；交互演示按教学难点选配，PPT/PDF 按本次要求。

## 1. 锁定目标、范围与来源

读取目标项目的 `AGENTS.md`、指定原卷/题面、必要图片与数据附件、已有解析和进度。记录年份/年月、考试与组别、轮次、语言/等级、题号、来源路径或链接、指纹、评分规则、学生基础、允许语法、运行版本与输出位置。写入前及最终交付前再核对同一目标，不能用其他年份、组别或旧报告代替。

按原卷实际题型、选项、小问、程序空和评分设置工作，不固定题量、分值或语法难度。扫描/OCR/公式与原图逐项核对；来源冲突时列出对应位置与影响，保持未核实标记。需要联网核对时优先原考试机构的原卷、大纲、答案或更正，记清版本；旧技能中的大纲只作线索。

| 请求 | 执行范围 |
| --- | --- |
| 只读审查/先给建议 | 仅在对话中交付问题、证据与建议，不写课程文件 |
| 仅规划 | 只写授权的清单与解析/演示计划，不生成程序或网页 |
| 编写/补全/修改 | 保留原卷与原稿，完成本次解析、完整代码、核验与修复 |
| 续做 | 核对来源和产物变化，从尚未完成或受影响的题目继续 |

优先沿用项目命名与位置。无约定时单题保存为 `<题号或题名>-题解.md`，整卷保存为含年月/年份、考试、语言/组别、等级/轮次的解析文件；程序放同一解析目录的 `src/<题号>-<方案>.cpp` 或 `.py`，临时构建另放。关键缺项才询问，已确定的信息不重复确认。

## 2. 选择模式并建立覆盖清单

读取 [考试模式与逐题解析](references/exam-modes.md) 中对应部分：`single`、`gesp`、`csp-first` 或 `csp-second`。GESP 覆盖一至八级的指定原卷；CSP 锁定 J/S 及初赛/复赛。单个客观题也按实际题型处理。

对照原卷先列所有要交付的叶子题号，阅读题的各小问、完善程序的每个空单列；共享题干和代码建立对应关系，不漏掉附属判断或选择。使用 [解析模板](assets/analysis-template.md) 与 [清单模板](assets/inventory-template.json)，建立“题号/小问 → 来源位置 → 答案与解析 → 核验依据 → 未完成项”的覆盖记录。

## 3. 编写解析与各层完整实现

按 [已有技能的交接约定](references/skill-handoffs.md) 使用当前可用的 `gesp-solver`、`solve-with-computational-thinking`、Obsidian 等能力，统一遵守本次要求、原题与目标项目约定。按需读取，不复制独立技能，不把提到技能名当作已经调用。

客观题逐选项解释理由；判断题说明条件，错命题给反例或修正；代码题展示执行追踪与语义依据。编程题读取 [多视角、分层得分与完整代码](references/programming-and-scores.md)，从题意、手算、模型、朴素瓶颈推导到各个有价值的解法、证明、复杂度和实现。

**每个被列为解法或分层得分方案的方法，都提供对应的完整、可独立编译/运行的程序文件，并在解析中链接。** 不能只给表格、伪代码、差异补丁或让学生从完整解中自行删改。参考代码保持与考试语言版本、已学范围和题目 I/O 一致；同分档的不同视角也分别说明实现与取舍，不机械凑方法数量。

分层表写明利用条件、对应测试点/子任务、复杂度、原评分依据、可论证覆盖的分数和代码/验证位置。区分理论覆盖下界、本地实测与未知分数；按原题的逐点/整组/依赖计分，不假设等分，不把不同程序的分数相加。组合解法有独立完整代码和覆盖论证。

## 4. 按需制作并关联交互演示

对状态变化、递归、排序、搜索、DP 等需要观察过程的难点，按 [交接约定](references/skill-handoffs.md) 调用可用的 `interactive-algorithm-demo`，交接确定的题面、算法版本、输入输出、下标、状态含义与观察目标。默认按教学难点选配；用户指定每题或指定题号时遵守其范围。只读/仅规划不生成 HTML。

演示引用明确的一种解法或标清多方法对照；可视化上限与原题范围分别标注。使用项目附件约定或解析目录的 `附件/交互演示/`，通过相对链接关联题号和使用步骤。题解、程序、演示共享数据与结果；静态关键追踪保留在正文。需要 PPT 时再进入可用的 `courseware-delivery`，视觉按其 `huashu-design` 协作执行。

## 5. 分层核验、修复与交付

按 [核验与清单检查](references/verification.md) 核对原卷、覆盖、答案、每层代码、得分依据、展示状态及必要交互。使用 [核验记录模板](assets/verification-template.md)，每个完整方案有显式测试清单和自己的编译/运行证据；预期来自原题、手算或独立方法。缺少正式数据时不能把本地样例当正式实测得分。

可运行 `python3 <本技能目录>/scripts/check_inventory.py <inventory.json绝对路径>` 检查人工清单与相对产物文件；它不读原卷、不执行程序，不证明答案、代码完整性、得分或浏览器正确。人工清单必须先与原卷核对，不能用脚本通过代替逐题审查。

修复本次引入或获准修改的问题，复验相关题目、方案与证据。代码结果与理论不符时先定位首个分歧，不修改原题/评分去迁就程序。最终给出解析、各层程序、必要演示与记录的链接，准确报告完成范围、实际测试、未核实来源和未验证项；本地通过不等于官方评测通过。不要自动发布到 OJ、发送题目、安装技能或同步 GitHub。
