# 教师诊断与家长表达

## 共用事实

两版使用同一份事实、题号、代码版本、评分和观察记录；详细程度与措辞不同。实际作答/运行、教师观察、诊断推断和后续计划分别标清。记录有冲突时保留分歧，不拼接成更好看的结果；修改结论时追溯受影响的反馈。

“独立完成”“提示后完成”“订正后本地通过”“独立复验通过”是不同证据。没有历史比较只说本次表现，缺答仅说未收到作答；没有时间或求助记录不评价速度、态度、努力和独立程度。只提供课程主题时，可写课程内容说明，个人学情待补。

## 教师版：每个主要问题一张可执行的问题卡

1. **表现与证据**：哪个题/知识关系、原答/代码位置、在哪个输入或步骤出现什么结果；已掌握与待确认分别写。
2. **原因与诊断边界**：解释错误机制，区分概念、题意、建模、策略、代码和测试习惯；可能原因给验证追问，不把推测写成心理标签。
3. **教学改动**：调整哪段讲解、增加哪个反例/状态表、怎样提示、何时撤掉提示；关联到讲义、演示或PPT位置，注明计划尚未执行。
4. **补练知识**：写具体条件与关系，例如“1起点且包含n”“0起点且排除n”的执行次数，而非统一记住使用小于等于。
5. **完整练习**：题面、已学前提、目标、分层提示、答案/完整代码、边界用例和常见错法。外部链接不能代替必需内容；只读请求在对话内给出，不写文件。
6. **复验与安排**：独立作答/解释/边界验证的达标标准、安排顺序、通过后迁移、未通过时回到哪个关系。没有复验结果时不写成已经掌握。

报告先给当前能力与优先级，再展开问题卡。多个问题可共享练习，但要指出每个目标如何被检验。编程、客观、手算与作品任务使用对应评价方式，不机械要求每题C++代码。

## 家长版：温和、鼓励、具体

按“学习目标→有依据的肯定→具体待巩固环节→老师与孩子的下一步→必要家庭配合”写连贯短文，按场景调整篇幅，不堆技术名词或教师诊断表。

肯定已表现出的能力、订正行为或有记录的有效努力；不足用“目前正在巩固……”“接下来重点练习……”等自然表达，并说明实际表现与帮助计划。已知严重或持续困难仍准确说明，不能用委婉措辞掩盖事实；成绩、分母、缺测和提示程度不能美化。

生活化解释可以帮助家长理解，但不能写成课堂真实发生的比喻或对话。家长配合建议应具体、适量，优先让孩子口述思路或完成订正，不要求家长教授超出其背景的算法。鼓励指向可执行行动，不保证获奖、考试通过或固定提分。

默认纯文本、自然分段、可复制微信；沿用用户指定称呼、标题与字数，不虚构姓名、日期或交流对象。仅生成草稿，用户自行核对和发送。
