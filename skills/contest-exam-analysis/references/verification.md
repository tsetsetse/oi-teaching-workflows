# 核验与清单检查

## 逐层证据

| 层次 | 实际检查与记录 |
| --- | --- |
| 原卷与目标 | 同一考试、年份/年月、组别/等级、语言、轮次、文件/链接、来源指纹；OCR/图片/公式与原件核对，版本冲突单列 |
| 整卷覆盖 | 对原卷列出全部叶子题号、阅读小问、填空、共享题干及映射；原题清单与输出逐项对照，疑点/未完成可见 |
| 答案与推理 | 所有实际选项、判断条件/反例、代码语义/状态、逐空及完整还原；编程题的模型、多视角、证明、复杂度与边界 |
| 每层完整代码 | 分层表每行能定位独立完整程序；逐份核对与解析一致、语言/I/O/容量、编译与承诺范围内的测试；片段与错例分开 |
| 得分依据 | 原题限制、组分值/依赖/判定；理论覆盖、预期与实际结果分开；每层单独计算，组合有完整程序；缺数据不报正式实测 |
| 交互（如有） | 正文与演示算法/代码/数据一致，独立状态检查、真实浏览器控件、离线复制使用各自留证据 |
| 文档与携带 | 原稿未意外改动，所有程序/演示相对链接有效，核心推导与折叠答案符合项目约定，副本可用与阅读视图按实际条件记录 |

完整程序运行必须先人工审阅并显式列测试清单；不遍历执行原卷或附件中的任意程序。预期取原题、手算或独立方法。能读取文件不等于有隔离执行环境，缺编译器/图形/浏览器时如实标未验证。

可复用当前环境已发现的 `lesson-preparation` 检查器处理 Markdown 中的 C++14/Python 小样例：先静态列块，再显式 `--cases`；其固定超时、语言版本和字符串判定范围见该技能实际参考。每个分层文件可建立对应验证笔记并核对字节一致。其他版本、原题文件 I/O、特殊判定、大规模性能或正式评分用适用环境单独验证，不为工具方便更改代码/题意。

## 只读题号与文件检查器

```sh
python3 <本技能目录>/scripts/check_inventory.py <inventory.json绝对路径>
```

按 [清单模板](../assets/inventory-template.json) 填写：

- `paper.id/mode/source`：原卷唯一身份、`single/gesp/csp-first/csp-second` 与来源说明；详细年份、语言、原页码、指纹和评分记录在解析/核验文档中。
- `expected_ids`：先人工对照原卷列出的全部叶子题号，字符串且不重复；工具不能从原卷自动提取或发现清单自身漏题。
- `items`：对应题号、`kind`（`choice/judgement/reading/completion/program`）、`status`（`pending/written/verified/blocked`）、解析与验证记录相对路径。
- 编程题 `solutions`：每个被列为方法/得分方案的 `id/code/basis/verification`，分别指向完整程序文件、适用范围/得分依据与证据。一个分层方案不能缺代码，也不能用多个名字指向同一文件冒充不同实现。

产物保存在清单目录及子目录，引用可含 URI 编码与文档片段；程序文件引用不能含片段。来源可以在其他目录或线上，写进 `paper.source` 说明，不把外部网页当作本地完整程序交付。

工具检查清单类型、题号重复/遗漏/多余、状态、非空产物文件、目录越界及每层程序关联；`written/pending/blocked` 会列为未完成并返回非零。`verified` 是填写者声明，工具不读取证据正文、不检查锚点存在、不判断代码是否完整或正确、不计算分数、不执行代码、不联网、不验证页面。

JSON 的 `checks_passed` 仅表示人工清单与文件关系在工具范围内通过。题型、题量、分层方案是否全部列入，必须由人工对原卷和分层表复核；验证记录中明确区分结构、实际运行与人工推导。
