# 已有技能的交接约定

主工作流负责范围、原卷身份、逐题覆盖、输出组织和最终核验；已有技能负责具体能力。通过当前环境的技能目录或用户指定位置读取 `SKILL.md` 与必要资源，不写死作者路径，不复制整套技能进本目录。缺少能力时先完成可做部分，说明受影响环节；不假称已经调用或自动安装。

| 能力与调用条件 | 输入简报 | 返回并读回的内容 | 主工作流复核 |
| --- | --- | --- | --- |
| `gesp-solver`：指定 GESP 原卷 | 原卷身份、语言/等级、实际题号、项目规则、学生基础 | 逐选项分析、判断依据、程序追踪、考点 | 原卷逐项一致，格式/题量按本次原卷，编程题继续补齐分层实现与验证 |
| `solve-with-computational-thinking`：编程题与复杂程序推导 | 完整契约、范围/评分、允许语法、已有方法 | 手算、建模、多视角、朴素到优化、证明、复杂度、参考代码 | 所有被列为方法的完整程序、分层依据和独立测试；按本次语言版本处理 |
| `interactive-algorithm-demo`：过程观察有教学价值或用户指定 | 题号与解法版本、完整代码、输入输出、下标/状态、观察目标、演示上限、输出位置 | 自包含 HTML、操作步骤、程序/算法/浏览器检查证据 | 与正文/代码同步，前进回退撤回答案，错误输入保留有效状态，范围上限分清 |
| `obsidian-markdown`：写 Obsidian 笔记 | 项目格式、原文链接/嵌入、折叠约定、附件位置 | 可读笔记、相对附件链接、必要折叠答案 | 原卷与原稿保留，核心推导展开；未看阅读视图不称已渲染 |
| `obsidian-cli`：需要实际操作资料库 | 明确的库、笔记和操作范围 | 实际读写/检查结果 | 本次授权与目标路径，结构检查和桌面结果分开 |
| `courseware-delivery`：用户要 PPT | 已确定解析、教学目标/课时、选用方法、分层代码、演示位置 | PPTX、原生备注与实际验收；新视觉按其 `huashu-design` 规则选型 | 不是题解默认附带产物，继续遵守题意与版本 |

`csp-contest-author` 用于用户要求命题、改编、组卷或制作正式数据包的任务。解析原卷时可借鉴其评分证据观念，原题和正式数据仍保持原样，不能为了区分部分解而修改已有考试数据或原评分设置。

## 演示的教学嵌入

默认由本次解析中的教学难点选配；没有明确语义或算法尚未确定时先解决契约问题。交互能帮助观察的典型内容包括循环/递归顺序、排序交换、搜索队列、数据结构变化、DP 转移和反例对比；概念判断或短算式可用静态追踪，不要求每题生成网页。

在解析对应题目处写“打开时机 → 示例输入 → 学生先预测的问题 → 前进/回退或改数据的操作 → 需要观察的不变量/结果 → 回到正文的结论”。按项目约定存附件或使用 `附件/交互演示/`，使用相对链接；只读审阅与仅规划只记录演示计划。

演示选定哪一层程序要写清楚；对照两个方法时分别标出状态与代码。演示中缩小 n 或数值仅为观察限制，不改成原题范围；正文保留静态关键步骤。JavaScript 模拟不称为实际执行 C++ 源码。

交互仍由演示技能验证算法、逐步状态、控件、真实浏览器和离线性；主工作流另核对与题解、程序、输入输出的一致性。截图、页面能显示或程序样例通过，都不能代替完整交互测试。
