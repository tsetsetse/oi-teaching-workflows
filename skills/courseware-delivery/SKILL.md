# 课件交付工作流

把确定的讲义转成学生可看、教师可讲、能够携带使用的课件。默认交付 PPTX、逐页教师备注和必要的验收记录；PDF、HTML、参考程序只按本次要求或明确的教学需要提供。

## 1. 锁定讲义与交付范围

读取指定讲义、目标项目适用的 `AGENTS.md`、已有课件/视觉模板和必要附件。记录课程编号、学生基础、已学语法、课时、来源指纹、输出目录、所需格式和现有进度。
延续目标项目命名与目录；没有约定时，在课程目录下的 `PPT/<课名>/` 保存成品，临时构建、候选与检查材料另放构建目录，保留原稿和已有成品。

| 本次请求 | 执行范围 |
| --- | --- |
| 只读审阅、先给建议 | 只在对话中交付结论，不写课程文件 |
| 仅分镜/规划 | 写本次授权的分镜与验收计划，然后停在计划阶段 |
| 制作/交付课件 | 完成分镜、真实文件、验收与修复，不停在大纲或生成脚本 |
| 修改/续做 | 先读现有文件和记录，核对来源变化，只补尚未完成或受影响的部分 |

课时、格式和已确认的视觉方向已有约定时直接沿用，不重复请求。仅指定风格词或品牌尚不等于选定方向，按第3节的视觉选型规则处理。普通分镜和版式细节自行处理；影响题意、学生阶段或交付形式的关键缺项才询问。
讲义未确定或缺少主讲题的关键条件时，先完成可做部分并列出缺项；必要时使用可用的 `lesson-preparation`，不擅自改题、覆盖讲义或把来源疑点写成已核实事实。

## 2. 从讲义设计投影与教师备注

先读 [教学推进方式](references/teaching-paths.md)，按学习目标选择项目实践型、算法推导型或有明确分工的组合；基础短课只取需要的环节。确定贯穿本课的核心作品或任务，记录每轮“已有成果 → 新问题 → 学生尝试 → 验证结果 → 得到的方法”。
读取 [投影与备注的分工](references/projection-and-notes.md)，使用 [分镜模板](assets/storyboard-template.md) 建立“讲义段落 → 页码/揭示步骤 → 教师动作 → 学生操作 → 检查点”的映射，安排学生解释作品/方法的环节与相应达标信号。
沿用讲义的情境、预测、观察与推导、方法代码、Bug 修复、练习迁移主线。页数由课时和教学动作决定；不把讲义段落逐段粘贴到幻灯片，也不统一强制固定页数。

- 学生屏放问题、必要条件、图表、代码与当前状态；逐页原生备注放讲稿、预期回答、误答追问、时间、操作与转场。
- 主讲题、独立编程练习和作业的完整题面在投影中可读，可按栏目连续拆页；题号、条件、输入输出、范围与公开样例保持完整，不能只放在备注或用“见讲义”代替。
- 预测先于答案。优先用相邻页面保持版式一致并逐步揭示；需要原生动画时核验真实播放，不以静态渲染证明点击顺序。
- 代码、数值、状态表和公式使用可检查、可编辑的原生对象；图片用于帮助理解情境和概念。长代码分段保留上下文，并按需要提供完整参考程序。
- 按学生已学范围说明每一步；Bug 页给预测、错误状态、原因、最小修复和复验，错误演示与正确参考程序分开标识。

## 3. 制作真实成品与必要配套

需要新视觉设计时配合使用 `huashu-design`：从当前环境发现并读取该技能及其 deck 模块，按 [设计协作与制作衔接](references/design-collaboration.md) 将教学分镜交给它。新设计先展示六候选缩略图和三个方向各两页真实代表页，然后结束回合等用户选定；把选择写入 `direction-approved.md` 后再展开整套。已选方向的迭代、机械修改或用户本次明确跳过，按该技能规则记录依据；“继续”不算跳过。
只读审阅、仅教学分镜或维护工作流文件不产生新视觉，不为它们启动视觉选型。缺少 `huashu-design` 时先完成不依赖它的教学规划，说明设计环节缺项，不自动安装或声称已经调用。

用当前环境可用的 `presentations:Presentations`、`pptx` 或相应导出能力，把选定设计制作成真实 PPTX；需要文档或表格运行库时先用 `load_workspace_dependencies` 查找环境提供的依赖。HTML 设计稿、方向截图和按设计模块生成的 PDF 默认留在构建/预览目录，正式交付格式仍按本次约定；用户明确禁止生成某格式时优先遵守。
沿用已选视觉风格或模板，按投影距离检查字号、留白、对比、代码缩进和表格密度。导出后补齐并读回逐页原生教师备注，核对代码、数值与状态对象仍可编辑；图片和音视频嵌入 PPTX，不能依赖作者本机素材路径。

只有教学观察确实需要交互或用户明确要求时，使用可用的 `interactive-algorithm-demo` 制作演示。演示和课件共享题面、代码版本、输入、状态与输出约定；保留静态关键步骤作为演示不可用时的授课支撑。
有本地附件时，将其纳入交付目录，使用相对链接并在备注中写明打开时机与课堂操作；最终按 [验收与失败处理](references/acceptance.md) 检查。
PDF 是静态阅读材料，不能代替动画、交互或教师备注；说明其是否包含答案/备注，以及与 PPTX 的对应关系。没有制作或导出能力时，保留分镜和源码，明确受阻环节，不改扩展名伪造成品。

## 4. 检查实际文件，修复后交付

按 [验收与失败处理](references/acceptance.md) 分别检查内容一致性、程序/状态、PPTX 包与备注、实际渲染、交付副本和必要的演示交互。
可运行 `python3 <本技能目录>/scripts/check_pptx.py <PPTX绝对路径> [--bundle-root <交付根目录>]` 做只读包检查；它不渲染、不执行代码，也不能证明备注内容、教学效果或原生播放正确。

修复本次生成或获准修改的问题，复验受影响部分。只检查文件存在、ZIP/XML 或缩略图，都不能代替必要的逐页观感检查和关键揭示步骤验证。
使用 [交付记录模板](assets/delivery-record-template.md) 记录每层的实际结果、证据、失败与未验证项目；续做前核对来源和成品指纹，避免重复生成已通过且未变化的部分。
最终给出成品链接、实际页数、教师备注/演示的使用方式、验证范围与影响使用的限制。只读或分镜请求按其范围交付；不要为一次备课自动发布网站、发送消息、安装技能或同步 GitHub。

模板和脚本从本技能目录读取；讲义、附件与输出从当前课程项目或用户指定位置读取、保存。安装副本不依赖工作流源码仓库或作者本机路径。
