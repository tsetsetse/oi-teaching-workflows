# 有守卫条件的算法模式图

## 使用方法

本表用于“提出候选算法”，不能替代建模和证明。每次选择都完成四步：识别现象、核对守卫条件、排除近似误选、说明被消除的瓶颈。

## 基础数据处理

| 现象 | 候选模式 | 守卫条件 | 常见误选 |
|---|---|---|---|
| 每个元素独立处理 | 线性扫描 | 单次局部处理足够 | 为了“快”无端排序 |
| 多次查询前缀或区间和 | 前缀和 | 数据静态或更新可分离 | 有在线修改仍使用普通前缀和 |
| 多次区间增减，最后统一求值 | 差分 | 可离线还原 | 需要随时查询却不维护动态结构 |
| 有序序列两端或双序列配对 | 双指针 | 指针移动具有单调淘汰性 | 指针可能回退仍声称线性 |
| 连续区间满足可维护条件 | 滑动窗口 | 扩缩方向单调，窗口信息可维护 | 含负数的和约束破坏单调性 |

## 搜索与最短路

| 目标与模型 | 候选算法 | 必须核对 | 常见误选 |
|---|---|---|---|
| 枚举全部方案、回溯选择 | DFS / 回溯 | 状态空间可承受；恢复现场完整 | 用 DFS 第一次到达充当最短路 |
| 每条转移代价相同的最少步数 | BFS | 边权完全相等；判重键包含完整状态 | 只看到“最少”就用 BFS |
| 边权只有 0 和 1 | 01-BFS | 权值严格属于 `{0,1}`；使用松弛 | 普通 BFS 的首次访问规则 |
| 非负边权最短路 | Dijkstra | 所有边权非负 | 有负边仍使用 Dijkstra |
| 多源等权距离 | 多源 BFS | 所有源点初始距离一致 | 只放入一个源点 |
| 附加能力影响未来 | 状态扩维 | 能力状态必须进入判重键 | 只用位置判重导致丢解 |

选择前写出：状态、转移、起点、目标、合法性、判重/距离键、边权。缺一项时不进入模板代码。

## 单调性与有序结构

| 现象 | 候选算法 | 守卫条件 | 常见误选 |
|---|---|---|---|
| 判断答案 `x` 是否可行呈单调变化 | 二分答案 | `check(x)` 单调；边界含义明确 | 只因数组有序就二分答案 |
| 查找有序表中的值或边界 | 二分查找 | 搜索区间有序；返回契约明确 | 闭区间与半开区间混用 |
| 最近更大/更小元素 | 单调栈 | 被弹元素能由新元素支配 | 不说明严格/非严格关系 |
| 队列窗口内极值 | 单调队列 | 过期规则和支配规则都正确 | 忘记按下标移除过期元素 |

## 贪心、动态规划与图结构

| 现象 | 候选算法 | 守卫条件 | 常见误选 |
|---|---|---|---|
| 连续作局部选择求全局最优 | 贪心 | 有交换、领先或割性质等证明 | “选当前最大”直接等同最优 |
| 子问题重叠且有最优子结构 | 动态规划 | 状态足够、转移无环或顺序可定 | 状态遗漏导致后效性 |
| 连通性随合并增长 | 并查集 | 只需维护集合关系而非路径细节 | 用并查集求实际最短路径 |
| 无向连通图最小生成树 | Kruskal / Prim | 目标确为生成树；处理不连通情况 | 与单源最短路混淆 |
| 有向依赖顺序 | 拓扑排序 | 图应为 DAG；必须检测环 | 输出不足 `n` 个仍当作合法顺序 |
| DAG 上计数或最优值 | 拓扑序 DP | 转移方向与拓扑序一致 | 未保护不可达状态 |

## 排除算法的句式

- 不能用普通 BFS，因为 ______ 的转移代价不是统一常数。
- 不能只用位置判重，因为 ______ 会改变未来可选操作。
- 不能直接贪心，因为还没有证明 ______ 的局部选择能保留某个最优解。
- 不能二分答案，因为 `check(x)` 在 ______ 处不满足单调性。
- 不能使用该 DP 状态，因为两个相同状态值仍可能因 ______ 拥有不同未来。

## 多解法比较顺序

1. 模型和操作契约是否相同。
2. 正确性前提是否满足。
3. 时间和空间是否适配数据范围。
4. 实现复杂度与出错风险。
5. 是否适合当前学生阶段。

若两种方法解决的操作模型不同，不把输出差异称为算法冲突。
