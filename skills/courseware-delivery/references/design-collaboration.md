# huashu-design 与课件交付的分工

`courseware-delivery` 负责教学目标、来源契约、分镜、教师备注、可编辑 PPTX 与最终验收；`huashu-design` 负责从教学内容长出的视觉方向、版式、素材与视觉稿。先确定教学推进和交付范围，再进行视觉探索；视觉调整不能删掉读题条件、学生思考步骤或精确代码来腾出版面。

## 读取与交接

从当前环境的技能列表或用户指定位置发现 `huashu-design`，读取它的 `SKILL.md` 和 `references/modules/deck.md`，再按模块读取实际需要的资源。资源和脚本均从发现的技能根目录读取，不在本技能中写死安装路径、复制第三方技能正文或维护另一套导出器。
执行实际设计时遵守该技能的偏好/外观/能力检查、素材与品牌规则、三方向流程、浏览器验证和设计检查。只维护工作流、只读分析或仅教学分镜时，不生成视觉、不运行设计收工步骤。

交给设计环节的简报包含：学生与观看距离、课时、教学路径、核心作品/任务、每轮改进、各页学习问题与信息容量、预测和答案的揭示顺序、已选模板/真实参考、可编辑对象、原生备注以及正式交付格式。用户提供的结构参考不自动等于选定了视觉方向。

## 视觉选择与继续制作

- 新视觉按 `huashu-design` 的三套候选逻辑生成六候选缩略图，挑三个有区别的方向，每方向两页真实代表页，连同备选展示后结束回合。代表页使用本课真实内容，宜覆盖情境/目标页和代码/状态推导页等差异最大的页面。
- 用户选定后在课程构建目录的 `direction-approved.md` 记录展示内容、预览路径、用户选择原话及确认位置，再以代表页确定视觉规则并展开全套。未选择时只交本阶段预览与待选事项，不写“整套制作完成”。
- 同一项目已选方向的延续迭代、非设计机械操作，或本次会话明确要求跳过，按该技能的豁免记录依据；保留已有选择原话或记录位置，不代填用户选择。用户只说“继续”时仍需遵守尚未完成的选择节点。
- 找不到技能或缺少生成能力时，完成不受影响的教学分镜，列明设计阶段缺项；不自动安装，也不以只有文字风格名的大纲替代真实方向稿。

## 从视觉稿到可编辑 PPTX

正式交付默认仍为 PPTX、原生教师备注与必要记录。按 deck 模块制作的 HTML 设计稿、方向截图、静态 PDF 是构建/预览材料，放在课程项目的构建目录；仅在本次约定需要时纳入正式交付。用户明确禁止生成某格式时，以用户要求为准，说明相应制作路径的调整。

在 HTML 开工前按实际情况选择设计技能支持的导出路线：从头制作时先满足可编辑导出的约束；已有视觉稿或需要继承 PPTX 模板时读取相应转换指南。也可使用当前可用的演示文稿制作能力落实选定设计；记录所选路线，保持尺寸与模板一致，不照抄其他路线的坐标假设。

完成导出后，从真实 PPTX 核对每页文本、精确代码、数值、状态表与公式，保持关键内容为可检查、可编辑对象，图片用于素材与示意。补齐原生演讲者备注，并读回讲稿、预期回答、误答追问、操作与转场。HTML 中写了备注不代表 PPTX 已含备注；整页截图也不能满足可编辑要求。

新设计完成视觉检查后，还须按 [验收与失败处理](acceptance.md) 检查真实 PPTX：页面与关键状态、编辑性、备注、媒体嵌入、代码与数据一致性、复制件和必要播放。HTML/静态 PDF 的正确不能替代 PPTX 的正确；三方向预览、选择记录与全套验收分别记录。
