# 竞赛与等级考试解析核验：实施方案

依据：本次会话已确认单题、GESP 一至八级整卷、CSP-J/S 初赛与复赛整卷；最新补充要求每种有教学价值的分层得分方案均有具体完整实现。用户已要求开始实施，按当前源码目录直接执行。

## 交付契约

- 新增 `contest-exam-analysis`：锁定原卷身份和来源，按实际题型建立题号/小问/空的覆盖清单；逐选项、判断、程序阅读、程序完善及编程题分别解析。
- 编程题从手算、建模、多视角、朴素瓶颈推导到优化、证明、复杂度、完整代码与核验。每层列原题子任务、分值依据、完整程序和测试；理论覆盖与本地实测分开，未知评分不编造分数。
- 通过当前环境发现已有 `gesp-solver`、`solve-with-computational-thinking`、`interactive-algorithm-demo` 与 Obsidian 能力，明确输入/产出/核验；不复制或修改已有独立技能。
- 补齐备课讲义的交互演示入口、调用简报、使用说明及独立验证。交互按教学难点选配；只读/仅规划不生成网页。
- 默认保存 Markdown 解析、完整分层程序与必要验证记录；HTML/PPT/PDF 按本次任务范围。课程来源与真实材料不进入源码仓库。

## 实施与验证顺序

1. **基线**：用现有技能对自编相同数对题独立试做，观察多视角、分层完整代码和评分证据；保留实际结果，不预设失败。
2. **技能与模板**：创建入口、按题型的参考、分层得分及代码要求、技能交接说明、解析与核验模板。
3. **覆盖检查**：用 Python 标准库只读检查人工核对的题号清单、重复/遗漏、未完成项、产物链接与分层代码文件；先写失败测试再实现。不执行讲义代码、不从原卷自动推断题数，不冒充题意或得分核验。
4. **接入备课**：更新入口与两模板，新增交互协作参考；保留现有讲义结构和脚本。
5. **示例**：自编小卷覆盖选择、判断、阅读小问与程序填空；自编编程题给出至少两档分层完整代码和可验证的评分依据，不把夹具当真题。
6. **复验**：执行新旧单元测试、原有讲义示例、新覆盖清单检查；独立后测实际产生并运行各层代码，测试不同题型、缺失评分与仅规划边界。
7. **审查与交付**：独立审查实际源码与产物，修复问题，核对原有安装与独立技能未改。记录静态、运行、人工审查及浏览器/真实考试未测边界。

## 范围与实现选择

- 在指定源码目录原地维护；本次不发布 GitHub、不替换个人技能安装，也不制作真实课堂交互/PPT。
- 新工具只负责清单和文件一致性；程序编译/运行复用已发现的讲义检查器（其 C++14 小样例范围明确）或题目指定编译环境。评分按原规则与证据人工核对，不再造通用判题平台。
- 新技能与资源从自身目录读取；课程输入、输出、来源和演示从目标项目读取。检测器不依赖仓库相邻技能。
