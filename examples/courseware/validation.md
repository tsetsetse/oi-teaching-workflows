# 课件交付：本地开发验证

本文件记录 v0.2.0 源码的工作流行为、工具测试和真实文件只读检查；发布版本不代表完整课件制作链已经通过。

## 工作流行为试做

两次独立代理收到同一份仓库自编40分钟讲义与“仅制定分镜和验收计划”的请求；新流程测试额外收到技能路径。

| 场景 | 实际观察 |
| --- | --- |
| 无新技能基线 | 已能规划逐页内容、备注和多数验收项目；未观察到整体规划失败。其计划额外要求教师PDF，使用原生单击揭示，并提出使源目录不可访问的携带测试方法 |
| 使用课件交付技能 | 规划25页相邻静态页揭示，逐页安排投影、原生备注、学生操作与检查点；没有自动增加PDF/HTML等成品，副本验收明确不移动、删除或更改原始资料权限；全部成品检查标为未来待执行 |

主代理实际读回了完整计划，核对25页时间连续、合计2400秒，与讲义一致；完整程序文本相同，输入讲义指纹不变，测试目录仅新增Markdown计划与说明。
案例是一对规划样本，不能据此证明普遍教学效果或完整制作流程已通过。

## 教学路径与设计协作调整（2026-10-28）

本轮仅修改工作流源码、模板与示例说明，补入项目实践/算法推导、改进轮次、学生表达，以及 `huashu-design` 到可编辑 PPTX 的衔接；没有生成新的视觉稿或课件。
修改前的独立只读模拟已能推断两种教学主线和设计选型节点，未观察到明显行为失败。本轮把用户确认的做法落实到入口与模板，不能将该基线写成失败对照或量化提升。

修改后的另一独立代理读取技能、模板与仓库自编讲义，对三个场景进行只读决策演练：

| 场景 | 实际观察 |
| --- | --- |
| 两种课程，新视觉尚未选择，正式只要PPTX与备注 | 分别围绕作品完善和同题算法改进规划；先展示六候选缩略图与三方向各两页代表页，等待选定后展开；HTML/PDF留构建预览，最终仍需可编辑PPTX与原生备注验收 |
| 自编讲义，只做40分钟教学分镜，不新增题目 | 只规划教学与后续验收，时间合计40分钟；不启动视觉选型、不生成设计或课件、不把预期检查写成已通过 |
| 已有方向A的确认记录，仅修正第8页错字 | 先核对现有记录与文件，保留原稿并沿用A；不重复选型，对修改及受影响部分复验 |

另一次独立只读审查核对了技能、参考、两模板、示例与用户指定的 `huashu-design`/deck 模块，未发现阻塞的衔接问题。主代理复核29项工具测试、原有讲义5组输入输出、两技能元数据与资源链接；原有讲义技能文件和PPTX检查器指纹未变。
这些证据只覆盖说明一致性与模拟决策；三方向真实出稿、HTML到PPTX转换、原生备注写入和完整成品验收仍需后续课程实际试用。

## 自动测试与审查

- 仓库29项测试通过：14项原有讲义检查，15项新的PPTX检查。
- PPTX测试覆盖：按关系定位页面/备注、缺少或空备注、必要部件/媒体缺失、外部资源、网页来源链接、相对附件、编码文件名、绝对路径、越出交付目录、损坏ZIP及未定义的XML关系引用。
- 独立审查发现URI解码顺序和未定义资源关系两项问题；补充回归先复现误验/漏验，再修复，全部测试通过。
- 原有讲义示例5/5输入输出回归通过；两条技能的元数据格式和资源引用检查通过。
- 测试环境为本机Python3.13与系统C++编译器，Python3.10最低环境未单独运行。

## 真实PPTX只读检查

对当前本地一份已有36页课件运行新工具，36页均识别到非空备注正文，没有外部资源依赖，工具检查通过且文件指纹保持不变。
精确文件路径和JSON结果保存在忽略目录 `.local/courseware-existing-pptx-check.json`，真实课件不复制入仓库。
历史记录曾指向旧路径和旧页数，本轮按实际文件位置与内容重新核对；没有沿用旧数字作为当前证据。
