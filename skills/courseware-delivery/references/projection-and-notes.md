# 投影页与教师备注的分工

## 沿着教学动作分镜

每页明确学生此刻要观察、预测或完成什么。讲义的核心认知与数据关系保持不变，按投影可读性拆分表达。
先按 [教学推进方式](teaching-paths.md) 确定核心作品/任务与改进轮次，再按教学动作拆页；同一轮中保持数据、代码版本与结果的对应。作品展示和方法解释应有学生可执行的问题及达标信号。

| 环节 | 学生画面 | 教师备注 |
| --- | --- | --- |
| 情境与契约 | 原情境、任务、完整条件与样例 | 如何引出问题，学生基础检查与来源限制 |
| 预测 | 输入、片段或空白状态表 | 等待时机、预期回答、可能误答与追问 |
| 观察与推导 | 逐步状态、关系、关键条件 | 每一步为什么变化，下一步让学生判断什么 |
| 方法与代码 | 可编辑代码、执行位置与当前变量 | 初始化、顺序、边界、模型映射和操作提示 |
| Bug与修复 | 错误片段、区分输入、逐步原因、修复对照 | 先预测后揭示，解释错误语义及复验方式 |
| 改进与再验证 | 已有成果、新要求/瓶颈、修改前后状态与同题结果 | 为什么需要改、学生先尝试什么、怎样核验改动 |
| 表达与理解检查 | 作品展示或方法解释的问题、可用证据 | 表达支架、追问理由与边界、需要回讲的信号 |
| 练习与小结 | 完整任务、操作要求、达标检查 | 支架、巡视点、分层要求、作业与转场 |

备注使用原生演讲者备注。投影上的完整题面、必要图表与学生操作要求不能只放在备注中。
预计讲稿、预期误答与操作建议不写成已经发生的课堂事实。

## 逐步揭示与静态材料

默认用相邻页面保持相同布局，只改变当前要揭示的部分。明确当前步骤的代码、变量、图形与已产生输出，回看时不能保留尚未得到的答案。
用户需要原生点击动画时，遵守其要求并验证真实播放；工具只能渲染静态图时，注明不能据此确认点击次序。
课件需要交互网页时，说明打开时机与操作顺序，保留课件内的静态关键状态作为备用。
PDF只能记录静态页面，需说明是否含答案/备注；题目页和答案页的区别仍应清楚。

## 可读性与可编辑性

- 优先沿用已确定模板和本项目风格；没有模板时按当前可用制作技能的设计流程处理。
- 页数由教学动作与课时决定，兼顾学生读题、思考、编码和等待时间；内容密集时拆页，不能靠持续缩小字号解决。
- 代码保持字符、缩进、行号与上下文可辨；表格中数值和单位明确。用标签、边框或位置辅助状态提示，不只靠颜色。
- 精确代码、算式、数字与状态表用原生文本、表格或形状；示意图帮助理解，不能让生成图片承担精确代码与数值排版。
- 多版本代码有明确比较目的、适用条件与本课采用版本；完整程序能从最终课件或随附文件取得。

## 转换讲义时的边界

保留课程编号、原有题号、来源、所有条件及样例；题面可按栏目拆到连续页，但整体必须独立可读。
发现实质错误或来源缺失时记录具体问题，处理可做部分；改变正式题条件仍按目标项目规则确认。
构建课件本身不授权重写来源讲义、批量更名、发布网站或补编新题。
