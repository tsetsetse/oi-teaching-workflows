# 检查器的使用与证据范围

只有明确传入 `--cases` 才执行代码。先人工审阅代码，再运行；临时工作目录不是安全隔离。
支持 Python 3（与运行检查器同一解释器）和调用系统 `c++` 的 C++14 编译（`-Wall -Wextra -pedantic`）。
每次编译上限30秒，单个用例上限2秒。固定超时适合入门课堂小样例；大规模性能测试用专门环境。

```sh
python3 <技能目录>/scripts/check_lesson.py <讲义绝对路径>
python3 <技能目录>/scripts/check_lesson.py <讲义绝对路径> --cases <测试清单绝对路径>
```

编号只计算 `cpp`、`c++`、`python`、`py` 语言围栏，从1开始，按文档顺序编号；`plain` 样例块不计数。
支持反引号、波浪号围栏和 callout 前缀。先用静态模式查看编号及行号，再填写清单：

```json
{
  "programs": [
    {
      "block": 1,
      "cases": [
        {"stdin": "3\n", "stdout": "Hello\nHello\nHello\n"},
        {"stdin": "1\n", "stdout": "Hello\n"}
      ]
    },
    {"block": 2, "skip": "局部比较函数；完整程序见代码块1"}
  ]
}
```

每个完整程序至少包含公开样例与有意义的边界/反例。用例预期结果来自题面、手工计算或独立算法，不能从待测程序输出反推。
输出按完整字符串比较，包括换行、空格和提示文字。不自动把错误输出修成测试预期；先核对原题及手算。
没有输入时写 `"stdin": ""`，不伪造样例输入。

程序执行清单必须逐项覆盖所有支持语言代码块；遗漏、重复编号、无效JSON、编译失败、异常、超时和输出不一致都会使检查失败。
局部片段、故意错误代码和平台程序可用非空 `skip` 说明原因；跳过项始终在报告中单列，不是运行通过。

JSON中的 `checks_passed` **仅表示本次工具检查未失败**：静态模式可以有 `untested`，运行模式可以有 `skipped`。
验收记录还应人工检查题面五个字段、数据范围、学生知识范围、来源、推理、总课时、链接与嵌入。
完整 YAML、链接可达性、图形/平台输出、浏览器和 Obsidian 阅读视图不在本脚本的检查范围内。

不要为了兼容本机而改教学代码：例如 macOS 编译器没有 `bits/stdc++.h` 时，记录环境限制，选择符合题目版本的编译环境后再验证。
