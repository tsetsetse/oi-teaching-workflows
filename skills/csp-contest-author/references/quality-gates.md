# 命题质量与数据校验

命题前阅读难度与契约部分；制作数据、终验时阅读后半部分。下面是可调整的教研方法，不是官方算法白名单。

## 难度定位

区分“知识点属于哪个范围”与“这道题有多难”。每题至少从以下四方面说明：

| 维度 | 需要判断的内容 |
| --- | --- |
| 前置知识 | 学生必须已经掌握的语法、结构与算法；不要把新的核心技术藏在实现细节中 |
| 关键观察 | 从题面到模型、从朴素法到正解，需要多少个独立且不直观的发现 |
| 推理负担 | 不变量、贪心依据、DP 状态充分性、边界和资源限制是否容易论证 |
| 实现负担 | 状态数量、下标与多种边界、常数优化、递归深度和预计调试时间 |

通常让 CSP-J 的梯度围绕准确模拟、基础模型识别及适度综合展开；CSP-S 可以承担更深的建模、复杂度优化和算法组合。这不是“J 禁止图论/DP”或“S 必须高级数据结构”的硬性划分。

正解和每档部分分都要列出必需前置及归类，不能只检查满分算法：

- **目标学生已学**：有课程事实或目标级别的适用范围支持，可直接作为前置。
- **可由已学推导**：写出从已有模型到新观察、状态或转移的推导，并估计推理与实现负担；不能把专门算法只改一个名字就称为可推导。
- **额外专门算法**：若超出课程或目标级别，优先换模型、解法或部分分路线；仅在用户已接受拓展时采用，并单独标明，不计入已学范围保证分。

“学完全部 CSP-J”不等于“学完全部 CSP-S”。例如出现堆优化 Dijkstra、一般树形 DP 等前置时，要核对适用版本的层级与课程，不能只用“图论/DP 已学”推定掌握。也不能仅凭状态维数多就判超纲：关键是能否由已学内容推导和在目标课时/赛时内实现。知识范围有争议时按下文官方来源核实；不需要拓展即可完成用户目标时直接选择范围内方案，不新增确认环节。

四题模拟赛可采用“基础落实 → 单个关键观察 → 综合建模 → 区分能力”的工作梯度，但不机械指定每一题的算法。把状态扩展、范围最小值优化、多源最短路等数个难点同时叠加时，需明确评估其对目标学生的负担；不能因为标了 T4 就视为合适。专题训练则优先形成同一模型的递进。

对严格按年份对齐的任务，核对当年的官方资料并保留来源，不把本地经验当作官方结论。可从 [NOI 大纲（2025 年修订版）官方发布页](https://www.noi.cn/xw/2025-04-18/841584.shtml) 和 [NOI 官方历年资料](https://www.noi.cn/zxzy/index.shtml) 开始查找，再确认用户要求年份的版本。链接是检索入口，不是以后永远沿用该版本的指令。只提炼与当前命题有关的依据，不把大纲全文打包进题目。

## 题意与证明

- 使用的量纲能否相加？例如总传输的数据量可以求和，速率意义的“带宽”不能直接冒充容量。
- 约束究竟针对同时发生、先后发生还是最终选中的集合？故事背景不能产生绕过数学限制的合理解释。
- 至多/恰好、可不操作、起点计费、重复计费、端点包含、同位置操作等，是否在题面与所有程序中一致？
- 总规模限制是否使标称复杂度可行？多个测试组不能各自取最大后意外突破总运行量。
- 答案和中间量上界是否经过推导？图距离、前缀和、乘法结果和无穷大哨兵需分别考虑。
- 贪心是否有可说明的正确性依据；DP 是否包含影响未来的必要状态；最短路方法的边权前提是否满足？
- 子任务是否有真实可行的低复杂度门槛和对应做法，而非随便划分点号？

题目经常允许多种正确算法。替代算法通过，应先判断其正确性与复杂度；不能为了让预设错解失败而不断挑数据，压制一个实际上正确的做法。

## 数据：用错误假设倒推测试

先列题目的关键限制与错误假设，再给每项安排可复现证据。下面是可迁移的例子，不要求每题全部照搬：

| 错误假设 | 应构造的输入及验证证据 |
| --- | --- |
| 奖励按全局日期周期发放 | 连续段从非周期起点开始；与“按日历判断”程序得到不同答案 |
| 可以忽略背包容量 | 不限容量的最优方案超过容量，且不限容量答案严格大于真答案 |
| 可以忽略相邻排斥 | 相邻高价值项引发竞争；裸背包答案与真答案不同 |
| 次数总是最大值或必须用完 | 中间参数取值、最优次数少于上限、使用零次更优 |
| 费用与权值都为正 | 规则允许时分别放零费用、零权值以及组合边界 |
| 网格一定有两行两列 | 单格、单行、单列；半径为 1 和恰好到达目标 |
| 大数据也能逐一枚举 | 让朴素法的最坏结构真实出现，实测其运行情况 |
| 输出总是落在 32 位内 | 仅对有大答案可能的题，放接近/跨过边界且可验证的答案 |

对于“容量 + 相邻限制”等复合模型，分别验证两个限制都真实影响答案，并包含同时生效的测试。只把数值放大制造溢出，可能让核心容量维度完全退化。

覆盖标签必须能从输入内容和运行结果得到确认：`capacity-binding` 不能只因为 C 的数字看上去小；`multiple-warps` 不能只因为 K 大于 1；`overflow` 不能只因为某个输入值很大。

随机数据补充分布，手工构造覆盖边界，对抗数据检验错误推理。不要把每道题固定成同一个随机比例。输出相同并不代表输入重复；只按输出去重会错误删除有价值的测试。

## 预期得分与实测闭环

生成前在数据计划的 `solution_expectations` 中记录代表程序、保证通过的子任务、预期得分区间与依据，覆盖主要部分解及意图区分的错误假设；按真实 `sum` 或 `group-min` 规则验收，不能只数通过点。

若保证通过组失分、实际分数越界或关键约束未起作用，先区分算法/实现错误、数据退化、判定方式和机器耗时差异，再处理：

- **数据或评分未兑现设计**：补足使约束真实生效的输入，校准合理时限裕量，重新生成并独立核验答案，再全量复验。
- **预设错解其实是正确高效的替代算法**：修正分类和命题分析，保留其通过结果，不为维护预设正解而卡它。
- **可接受的机器或分布差异**：仅在仍满足既定目标时保留，报告预期、实测、差异原因、接受依据与区分度影响；修改既定目标需用户明确指示。

不能通过事后放宽预期区间或直接复制实测分数消除偏差，也不能把“已有超时点”本身当作得分目标已兑现的证据；打包计分应按整组结果判断。既定得分目标或核心区分要求仍未兑现时，标为候选题，不宣称可正式使用。

## 独立校验

1. 用手算样例锚定题意；暴力按定义实现，先检查最小输入和空方案。
2. 在小规模可行域做随机对拍和有针对性的穷举；允许不同代码风格，但不能复制同一个错误状态转移。
3. 大数据至少覆盖可计算边界/构造答案，或采用独立实现/题目适用的变形关系。未独立核验的大数据应如实标注方法局限。
4. 运行所有正式输入的合法性与子任务检查，再复算答案。非法数据不能靠标准程序碰巧有输出而被接受。
5. 运行典型错解并计算实际分数。正确但慢的暴力失败于时间限制，与答案错误分开记录；本机超时结论不要假装适用于一切机器。
6. 从源码、种子和参数完整重建，再比对正式 `.in/.out` 的哈希。部分重生成不能标成全包可复现。

对随机失败保存最小可重现输入；能快速缩小则缩小，不能缩小也保留原种子与参数。修复验证器时，同样测试它能拒绝越界、缺项、多余项、非法结构和不满足子任务的输入。禁止“这个点特殊，跳过范围限制”式豁免。

涉及溢出错误时，C++ 有符号溢出属于未定义行为，不能把某一次编译器的回绕输出当作稳定规则；可用 sanitizer 定位，或写有明确定义的有限位模拟器验证错误思想。编译/超时/运行错误也要报告。

## 完成判定

可正式交付的题包，应同时满足：题面契约完整，证明与代码一致，正式输入合法，样例与答案经过运行，存在独立正确性证据，关键限制确实被数据检验，评分计算一致，全量生成可复现，报告指向当前文件。

测试数量不是等级证书，也不能代替人工审阅。用户要求“未经人工校验的候选题”时仍报告已做的自动检查；用户要求可直接使用时，不能省略运行证据或把未验证内容藏在历史日志里。
