# 编程教学工作台

根据本次请求选用五个工作流和四项配套能力。保留各模块的独立调用方式；只读取当前阶段需要的技能和资源。

## 1. 确定任务与执行范围

先读当前项目适用的 `AGENTS.md`、指定材料、已有产物和进度。沿用已确认的学生基础、课时、语言、输出位置与授权；只对影响执行的关键缺项提问。

明确用户要交付什么、当前在哪一步、这次允许做到哪一步。只读讨论或审阅只在对话中交付；仅规划只制作获准的计划；创建或修改任务保留原稿，完成本次范围内的制作、核验与修复。用户指定某个专门技能时直接使用它，不强制重新经过本入口。

课程记录原稿与课号；试卷锁定年月/年份、考试、等级或 J/S、初赛/复赛、语言、原卷来源和评分规则。自编示例按自编材料标识。来源、输出与技能资源分别定位，不把课程产物写进技能目录。

## 2. 选择当前阶段需要的模块

| 本次目标 | 读取并执行的模块 | 交付或交接条件 |
| --- | --- | --- |
| 标准课程路径/讲义母版、多课阶段安排、学习路线或调整未来课次 | `curriculum-planning` | 复用成熟材料，区分课程假设与个人证据，核算时间并设置达标/调整分支 |
| 从原稿备课、整理教师讲义 | `lesson-preparation` | 讲义、练习/作业/拓展及相关核验；交互按难点选配 |
| 根据确定讲义或解析制作、修改、验收 PPT | `courseware-delivery` | 分镜、真实课件、原生教师备注与验收；新视觉沿用其选型规则 |
| 单题、GESP 一至八级整卷、CSP-J/S 初复赛解析 | `contest-exam-analysis` | 来源与题号覆盖、详细解析、多视角和分层完整代码、核验记录 |
| 本课作业、阶段测试、考前/赛前模拟，或教师诊断与家长学情反馈 | `practice-assessment-feedback` | 设计与实际评价分阶段；详细教师问题卡和补练、事实支持的鼓励型家长草稿 |
| 只制作或局部修改交互演示 | `interactive-algorithm-demo` | 直达演示，不附加讲义和 PPT 制作 |
| 只梳理建模、算法选择与计算思维 | `solve-with-computational-thinking` | 按所需推导深度完成，不默认增加其他成品 |
| 只进行 GESP 题型分析 | `gesp-solver` | 完整原卷交付与核验仍由解析工作流组织 |
| 命题、改编、组卷或验题包 | `csp-contest-author` | 仅在用户请求这些任务时使用；正式 CSP 原卷题解走解析工作流 |

从环境技能目录发现对应模块；直接使用完整解包源码时，从本技能的同级目录读取 `<模块名>/SKILL.md`。资源路径相对各模块自身解析，材料和输出相对当前教学项目解析。读取完整指令后执行；提到名称不等于已经调用。

缺模块时说明受影响的阶段，继续已授权且可完成的部分；不自动安装、不借缺项扩大任务。花叔设计、Obsidian、PPT/PDF、浏览器等外部能力由对应工作流按当前环境发现，不假称套件内已经包含。

## 3. 衔接复合任务

按用户要的产物安排顺序。原稿到讲义再到 PPT：先备课，再课件交付。原题到解析再到 PPT：先解析核验，再把确定的解析交给课件交付，无须额外强制生成一份讲义。只要题解、只改演示或仅审阅时，停在本次目标。

标准母版或多课路径进入 `curriculum-planning`。没有具体学生数据仍可整理标准层；面向具体班级时按证据与时间形成实施层。用户只要计划时停在规划，不自动制作整套讲义/PPT；获准细化某课再交接对应课次卡。未来学习安排用规划模块，实际表现反馈用测评反馈模块；混合请求分清事实与计划。按反馈调整多课进度时保留已完成记录，只修改获准的未来/受影响课次。

要独立作业/测评或根据个人表现证据反馈时进入 `practice-assessment-feedback`，沿用本课目标、题目/评分及学生证据。只要本课讲义内练习时仍由备课处理；单独CSP题包命制可直达命题技能，连同测评和个体反馈的任务由新工作流组织其命题环节。缺少作答、课堂观察等个人表现证据时，只完成本次获准的设计或交待补事实，不生成个体学情；只有课堂观察也可完成它支持的反馈，不额外要求作答文件或出题。反馈要求的教学调整只交接获准修改的部分。

每次交接沿用同一来源、题面/I/O、学生基础、语言版本、选用算法与完整代码、数据/状态/结果约定、输出位置和已有检查证据。接收模块先核对这些输入，补齐当前交付必需的缺项；不要通过互相调用回到已完成且仍有效的阶段。交互成品可跨讲义、解析和 PPT 复用。

新视觉选型按 `courseware-delivery` 及 `huashu-design` 的要求等待用户选择；已经有效确认的方向直接沿用。普通教学或版式细节自行处理，不能为每次模块交接额外增加确认。安装、GitHub 同步、外部发布和定时运行按用户对这些动作的授权执行，不由教学任务自动附带。

## 4. 记录进度并续做

创建/修改任务时优先更新已有任务记录；跨流程且缺少记录时，可在本次输出目录使用 [任务进度模板](assets/progress-template.md)。记录面向当前任务，不修改全局规则。只读任务在对话中报告这些信息。

用户说“继续”时，先读最近相关的任务记录、实际产物和未完成项。将记录中的来源指纹与当前材料比对，沿关联的讲义、代码、分镜、备注和演示定位影响；把受影响的检查改为待复验，从最早受影响的必要阶段处理，其余有效成果沿用。

原稿变化不自动意味着重做整套或重选视觉。核对已选方向/代表页与变化后的教学目标、内容和约束是否仍适用；只有实质需要改变已选方向时才重新选型。缺记录时从现有文件与会话恢复可证实的状态，不能把“有文件”“选过方向”或旧检查通过当作完整交付。

## 5. 按证据交付

由当前工作流完成它要求的检查，区分静态检查、程序实际运行、人工审查、实际渲染/浏览器与尚未验证项。局部修改复验受影响部分，输入/代码/状态契约变化时同步核对关联产物；未授权重做的材料只提示受影响位置。

最终给出本次完成的产物、验证证据、仍缺的阶段及下一步。任务记录的完成状态只能来自实际结果；本地测试不等于官方评测，包结构正确不等于 PPT 可用，计划或分镜不等于成品。
