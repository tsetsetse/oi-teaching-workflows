# 算法交互演示

把算法的状态变化做成教师能暂停讲解、学生能修改数据验证的网页。可见图形、代码高亮、变量、解释和已揭示答案必须对应同一个步骤。

## 确定这次要演示什么

- 从当前对话确定主题、目标学生、教学语言、已有题目或文件，以及主要观察目标。已经明确的选择直接沿用；用户要求制作时交付可操作成品。
- **CHECKPOINT：关键契约缺失时先确认。** 只询问会改变正确性或授课范围的缺项，例如连通块统计对象、四方向还是八方向、二分要找什么边界。已有题面或对话能确定的条件直接沿用，不重复确认；布局、配色等常规选择自行处理。
- 先读用户指定的题面、代码或原网页。截图和 GIF 能说明可见交互，不能证明原作者的实现方式、平台或源码。
- 区分原题数据范围与为了看清过程而设置的演示上限。后者在页面标为演示限制，不改写成原题条件。涉及新增讲义题面时，遵守目标库的题面确认规则。

## 默认成品

没有其他交付要求时，制作一个自包含的 `.html` 文件：CSS、JavaScript 与必需图形均内置，使用系统字体，可直接复制到另一台电脑。优先使用原生 HTML/CSS 和按需的 SVG/Canvas；无需为普通算法演示引入框架、CDN 或构建步骤。

默认提供以下相互配合的部分；按算法实际需要精简：

| 部分 | 教学用途 |
| --- | --- |
| 数据设置 | 有意义的默认案例、自定义输入、明确约束、应用数据与恢复样例 |
| 代码与图形 | 当前代码行、对应数据结构、位置与变量的可见变化 |
| 当前步骤 | 这一动作做了什么、为什么、下一步值得预测什么 |
| 播放控制 | 上一步、下一步、播放/暂停、调速、重置；步骤较多时提供进度跳转 |
| 观察方式 | 代码＋动画、只看动画、只看代码，适配投屏或学生自学 |

采用适合中文课堂的清楚字号与留白。较宽窗口优先并排呈现设置、代码与动画；较窄窗口可上下排列，表格在自身区域横向滚动。当前高亮代码行应处于代码面板可见范围。保证原生控件有标签，状态除了颜色还有文字、边框或位置提示。

若用户指定已有网页，按原结构修改。若用户指定在线部署、内嵌可视化或其他载体，以其要求为准；本 Skill 默认的本地成品不需要注册站点或发布。Obsidian 相关产出放在合适的附件目录，除非任务要求，不自动改写或嵌入原笔记。

## 把教学过程变成可靠的步骤

新算法或较大的机制变更，读取 [步骤设计与检查](references/step-models.md) 中与当前算法有关的部分。普通配色、文案或局部布局修改无需重新设计算法。

1. 先确定输入输出、下标约定、状态含义与关键不变量，用一个小案例手工走通。
2. 按具有教学意义的动作分步，例如“检查邻居”“标记进入”“递归返回”，不要为了动画把一次状态更新拆到语义不一致。
3. 采用简单的数据流：`校验输入 → 生成步骤 → 当前步骤编号 → 渲染`。算法步骤生成尽量独立于界面，便于和朴素方法对照。
4. 每个步骤保存能恢复该时刻的状态、对应代码标记与说明。小规模演示优先独立快照；二维数组和嵌套对象也要复制到需要的深度。前进、后退和跳转都只改变当前步骤，历史不能随之后的计算改变。
5. 用稳定的标记关联代码语句和步骤，避免改一行代码后高亮错位。教学动画可以在同一条语句上分段解释，但应明确它是该算法的过程模拟；除非实际运行了编译器，不称为执行用户的 C++ 源码。
6. 揭示答案跟随当前步骤。预先生成完整轨迹时，也不能在初始界面泄露最终结果；回退后同步撤回尚未产生的答案。

只保留一个有效播放定时器；暂停、重置、修改/应用输入与拖动进度时处理旧播放。输入校验成功后再替换当前模型，错误时说明原因并保留上次有效数据。快捷键不抢占输入框的编辑键，也不重复触发按钮原有的空格操作。

## 复用现成前缀和示例

与前缀和相近的任务，先复制并阅读 [可运行网页](assets/prefix-sum.html)，再按任务修改。它展示数组与查询输入、步骤快照、代码映射、播放控制和响应式布局。其他算法可借用其交互结构，重写算法状态与图形，不必把数组表格套到所有主题上。

它的默认约定仅属于这个示例：下标从 1 开始、数组长度 1–16、1–8 组查询、C++14 代码容量 17。修改范围时同步检查页面提示、校验、模型、示例代码容量与数值类型、标准输入和测试，不能只替换界面上的数字。

示例自检命令（把路径换为当前 Skill 的实际路径）：

```sh
node <skill-dir>/assets/prefix-sum.test.cjs
```

自检运行示例中的纯算法部分，覆盖输入拒绝、边界、历史状态和独立逐项求和对照。它不是浏览器交互验证，也不是其他算法的通用正确性测试。复制并修改示例时同步适配测试文件与目标路径，保留手算期望或独立朴素方法作为比较依据。

## 验证与交付

- **算法与代码**：核对默认案例和关键边界；复杂算法用独立方法或不变量检查。页面显示完整 C++/Python 程序时，提取实际显示的代码，按约定版本编译/运行，核对页面结果。教学模拟与参考程序不能各讲一套。
- **状态与交互**：实际检查前进后回退、任意跳转、自动停在末尾、重新播放、调速、重置、模式切换，以及错误输入后原数据仍然可用。对已验证且未受本次改动影响的部分不反复扩大检查。
- **界面**：使用当前环境支持的浏览器工具查看真实页面，确认图形、代码、解释和播放控件可读可用。检查宽屏与窄屏时记录实际窗口尺寸，不把请求的尺寸当成已生效。页面只显示出来不等于交互已通过。
- **离线性**：单文件成品核对外部资源、导入和运行时请求；环境允许时直接打开文件验证。工具若禁止本地文件协议，保留已完成的检查，如实说明未实测项，不绕过限制。临时预览链接不能替代最终文件。
- **结果**：给出稳定文件链接、简短使用方法、已完成验证和仍存在的限制。有实际截图时可以附上；不以静态效果图替代可操作网页。保持原有文件和无关内容不变。

遇到验收失败，先定位原因，只修复本次生成或获准修改的成品，再复验受影响部分：

| 失败现象 | 修复与复验 |
| --- | --- |
| 显示的程序编译或运行失败 | 从成品重新提取代码，依据诊断修复，再按约定版本编译、运行原失败案例及相关边界。不能用动画输出替代程序验证。 |
| 算法结果、图形、解释或代码不一致 | 用手算或独立方法找到首个分歧，修复模型或映射；复验该步骤、最终输出和相关边界。不能只改答案文字掩盖分歧。 |
| 回退、跳转或播放状态异常 | 检查快照复制深度、步骤编号及旧定时器处理，复跑原操作顺序，并核对恢复的变量、图形、已揭示答案和播放状态。 |
| 高亮错位或恢复视图后不可见 | 检查语句标记与滚动定位；恢复代码面板后按当前步骤重新渲染并定位。复验隐藏代码期间推进、重置或跳转后再显示的操作。 |

修复后仍未通过时，交付说明写清失败项与影响，不称为全部验证通过。环境缺少编译器或浏览器能力时，分别标为未验证，不混作程序本身失败；保留已经完成的检查，不绕过工具限制。
