# 项目教学与作品验收实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** 新增project-teaching，使Python各知识点和C++相应阶段通过有意义的需求、阶段作品、解释与迁移组织教学，并接入统一入口。

**Architecture:** 新模块负责项目与知识的关系、版本推进、教师支架和作品验收，复用备课、计算思维、课件与反馈能力。包构建器自动发现技能目录，保持不变。

**Tech Stack:** Markdown、YAML；验证复用Python 3.10+标准库检查器，不新增运行依赖。

**Spec:** 本文“已确认设计”及当前会话确认；真实第03课试点仅在.local保留，不纳入源码示例。

## 已确认设计

- 每学一个知识内容，孩子能知道它帮助解决什么问题，并在完成任务中理解其作用。
- Python覆盖语法阶段各知识点及综合应用，Turtle衔接只是一个场景；允许小项目、连续升级和操作实验，不强制每个知识点另开大项目。
- 情境需求→发现缺口→预测/手算→代码机制→功能推进→提炼规则→独立迁移。
- C++按基础语法/算法应用/综合实践选择深度，补齐形式化契约、类型与初始化、范围/下标、编译环境、正确性及复杂度。
- 保留功能、解释、独立程度、迁移四维证据；教师提供的界面/初值/代码不算学生独立完成。作品正确不自动代表概念掌握。
- 已有讲义项目化改造和围绕知识点设计均可直达；只验收已有作品也按证据完成，不强制重写课程。

## Global Constraints

- 使用者项目AGENTS和已有授权优先；只读讨论不写产物，制作保留原稿；不把课例背景固定为所有课程要求。
- 套件源码0.7.0-dev；已发布及本机v0.6.0保持原样。本次不创建新发布标签，不同步远程，不替换个人安装。
- 无真实学生信息、密钥或课程成品入库；真实课例仅留.local；四项能力快照不改。
- 新资源相对技能自身读取；课程来源和输出相对目标项目。程序只在显式清单下执行。
- 测试新技能的独立代理仅处理合成任务并在.local或临时目录留证据，不发送外部消息。

## Review Focus

- 已学语法较多的Python班是否仍能使用，避免只匹配Turtle衔接。
- 项目是否真正产生新知识需求，避免故事名替换后仍先灌输语法。
- 支架由教师提供时，独立证据是否准确；缺学生数据时不虚构反馈。
- C++教学层次与原题部分分是否分清，缺评分信息不猜分数。
- 源码开发版与已发布安装步骤是否清楚，解包资源是否完整，避免指向不存在的新标签。
