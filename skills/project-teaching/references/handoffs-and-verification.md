# 交接、核验与验收证据

制作、验收或跨流程续做时读取。按环境发现模块；完整源码解包可从本技能同级目录读取。缺模块时说明受影响部分，完成能做且已授权的工作，不自动安装。

## 交接只推进当前需要的阶段

| 需要的产物 | 调用模块与交接内容 |
| --- | --- |
| 多课项目路线 | curriculum-planning：知识/先修、项目各版本、总课时、证据、未来分支；只要单课时不强制先生成阶段规划 |
| 详细讲义 | lesson-preparation：已确定的需求/知识对应、题面契约、时间、程序、教师支架、撤架任务和验收；备课沿用该设计，不再次路由回项目设计 |
| 模型和算法 | solve-with-computational-thinking：学生范围、任务、约束、选用代码；C++编译版本服从本次项目，而非各技能默认 |
| 交互/PPT | interactive-algorithm-demo / courseware-delivery：确定的模型、版本、状态、观察目标；视觉协作按对应模块规则，纸面状态表仍保留 |
| 作业、教师/家长反馈 | practice-assessment-feedback：目标、任务/评分、实际代码/观察、提示与复验；缺个人证据只完成设计或待补信息，不预填学情 |
| 真实原卷/部分分 | contest-exam-analysis：精确来源、年份/等级/轮次、规则与数据；只有命题/组卷请求才进入csp-contest-author |

本次只要方案或验收时，不启动表中所有制作。交接沿用同一来源、语言、知识范围、契约、版本、教师支持、状态、时间和现有核验证据；避免来回重复生成。

## 核验层次

1. 来源与教学人工审查：每项核心知识是否由功能缺口引出；机制、代码、状态与结果是否一致；原题和改编条件有依据；总时间与撤架/迁移是否可执行。
2. 文档/资源结构：元数据、围栏、任务字段、链接和附件。结构通过不代表题目或教学通过。
3. 代码实际运行：审阅后复用lesson-preparation的scripts/check_lesson.py。仅结构检查不传--cases；执行时显式提供覆盖全部支持语言代码块的清单，完整程序按契约验证样例与有意义边界，片段逐项说明跳过。C++检查器默认C++14；本次需其他版本时使用相应编译命令与清单并记录，不能把不同环境混称已验。
4. 输出/显示：文字输出保留有意义空格、换行、精度；图形、平台API、PPT或网页在对应环境核验，静态状态表不是实际浏览器交互。
5. 学生与课堂：实际预测、程序、提示记录、解释、独立复验、迁移和耗时；教师参考程序或模型测试不产生学生掌握结论。

预期结果来自题面、手算或独立方法；故意错误程序与修复程序分列。可能无限循环或产生未定义行为的Bug先手算/有限步追踪，只有具备明确停止控制的独立实验才实际执行；不为不确定行为编造固定错误输出。

常见边界按本课机制挑选，如零次/一次、多次更新、首末位置、重复值、允许范围的极端值；复杂算法再按需对照或随机核验。固定数据任务不虚构可变输入边界，题面未允许的数据不能当作正式失败样例。

## 验收、修复与续做

四维记录引用具体结果/原话/代码位置；不足时写问题、依据、下一步练习与独立复验条件。功能测试不能替代解释，提示后订正不能写成独立掌握，没有观察不能以“预计”补成学情。

源文件、规则或版本变化时先比对指纹，定位受影响的程序、题面、状态、演示、讲义和测试。局部变化只复验相关部分；超出授权的旧产物列影响，不静默覆盖。报告实际通过、失败、跳过与未测；课堂节奏与兴趣变化只有真实试课后才能评价。
